# Запрос от команды mockup: порт и включение встроенного ONVIF-сервера

2026-11-16 · коммит контракта `ff43911` (0.13.0) · от команды mockup, для владельца контракта

Кому: владелец контракта

**Статус: новый**

## Что мы делаем

Мы закрываем пробел A21 против Axxon One (`docs/axxon-one-gaps.html`): администратор видит и меняет порт встроенного ONVIF-сервера в карточке сервера, чтобы другие VMS брали видео этого сервера. В Axxon One у объекта «Сервер» есть параметр **ONVIF server port**: вкладка «Устройства» → имя сервера, по умолчанию 8081, у каждого узла свой порт (документ lexiro 292000).

Сейчас в контракте этого нет: профиль `vms.webserver/1` (свойство `webServer`) знает только веб-сервер и RTSP-сервер. Прототип 75 (`index_75_onvif-server.html`) рисует карточку «ONVIF-сервер» на вкладке «Веб, RTSP, ONVIF» карточки сервера на заглушке: порт и флажок живут в памяти страницы.

## Источники

Axxon One 3.0, документ lexiro 292000 («Configuration of the ONVIF server»): порт 8081 по умолчанию, уникальный порт на узел, Drivers Pack 3.74 и новее, камеры с MJPEG ONVIF-сервер не отдаёт. Документ lexiro 568876 («Server») — параметры сервера рядом с «Web-server properties». Живого сервера Axxon мы не проверяли.

## Что нужно

Имена полей — наше предложение. Владелец контракта может выбрать другие.

1. **Порт ONVIF-сервера.** Необязательное поле `onvifPort` в `webServer` профиля `vms.webserver/1`: целое 1–65535, по умолчанию 8081. Сервер проверяет его вместе с остальными портами `webServer`: порт не совпадает с `httpPort`, `httpsPort`, `rtspPort`, `rtspHttpPort` и не попадает в диапазон портов видео (`webRes`). Ошибка — как у других портов, с полем `/properties/webServer/onvifPort`.
2. **Включение.** Необязательное поле `onvifEnabled` в `webServer`. Сервер отдаёт в нём настоящее состояние ONVIF-сервера, а не умолчание. В Axxon One 3.0 переключателя нет: по документу 292000 сервер запускает ONVIF-сервер только с переменной `NGP_ONVIFSERVER_ENDPOINT` на компьютере сервера, а в новых версиях, по словам нашей команды, ONVIF-сервер работает сам. Поэтому поле — наше предложение сверх AO, и консоль не угадывает состояние: нет поля — консоль не показывает флажок. Если владелец решит, что включение — не дело консоли, достаточно п. 1, а консоль уберёт флажок.
3. **Перезапуск.** Правка `onvifPort` или `onvifEnabled` идёт так же, как правка других полей `webServer`: PATCH `properties.webServer` (JSON Merge Patch), сервер перезапускает ONVIF-сервер. Событие в потоке с новой версией объекта — как у веб-сервера.
4. **Камеры с MJPEG.** Консоль показывает камеры сервера с кодеком MJPEG по `GET /units?serverId=…&implements=vms.camera/1` и свойству `codec`. Новых полей не нужно. Если ONVIF-сервер отдаёт и MJPEG в каком-то бэкенде — скажите, консоль уберёт предупреждение.

## Что сломается

Ничего. Поля новые и необязательные. Они описывают то, что сервер уже делает: `onvifPort` — порт ONVIF-сервера (в Axxon One по умолчанию 8081), `onvifEnabled` — работает ли ONVIF-сервер сейчас. Чтение полей не меняет поведение сервера. Новая проверка повтора портов касается только запроса, где есть `onvifPort`. Клиент, который полей не знает, пропускает их по правилу контракта о незнакомых полях.
