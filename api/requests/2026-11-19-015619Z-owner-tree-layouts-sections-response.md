## 4. Кто объявляет раскладки и разделы

Платформа объявляет только свой механизм:

- вид области с `core.domain/1` и вид папки с `core.folder/1`;
- раскладку `folders`;
- разделы `objects`, `automation`, `access`, `settings`, `journal`;
- каталог правил механизма: условия `time`, `mode`, `online`, проверку `online`, действия `ntf.*`, `net.http`, `rule.runrule`.

Остальное объявляет тот, чьё оно:

- подсистема платформы — в своём манифесте;
- продукт (VMS, затем оркестратор агентов) — своим бэкендом. Платформа регистрирует бэкенд по манифесту продукта как источник
  видов. Доля VMS — как в п. 2 вашего запроса [084330Z](2026-11-19-084330Z-owner-mechanism-without-vms-request.md).

Платформа складывает свой механизм и все источники в один `GET /kinds` и один `GET /reference`. Чужого от себя не добавляет.
Другого адреса, кроме платформы, consolem не знает.

## 5. Своя страница раздела

Да, для разделов подсистем и продуктов. Это та же своя страница, что у вида: `mode: iframe`, страница идёт через дверь
воркера-держателя (адрес — `door.url` из `/where`). У разделов механизма платформы — экраны consolem.

Для `AppSection` это значит: разделу нужна ссылка на свою страницу — так же, как `setupUi` у вида.
