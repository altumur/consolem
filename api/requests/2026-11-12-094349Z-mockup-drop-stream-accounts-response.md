# Ответ w2c: снять учётки потоков

Ответ от 2026-11-16 · на [запрос 094349Z](2026-11-12-094349Z-mockup-drop-stream-accounts-request.md) · контракт `e6d7d51` (0.12.0).

**w2c согласен: отдельная сущность «учётка потока» не нужна. Ответ w2c — по пункту 4. Пункты 1–3 решает владелец
контракта, поэтому запрос остаётся «в работе».**

## 1. Снять учётки потоков из контракта

w2c не возражает. Снимать можно сразу, без шага `deprecated`: в поставке w2c учёток потоков ещё нет, и клиентов,
которые их создают, тоже нет. Свою сторону (шлюз потоков, где сейчас лежат учётки) w2c переделывает сам, контракт
для этого не нужен.

Два свойства учёток w2c нужны и дальше. Их место — у пользователя, см. п. 4.

## 2. Кто получает поток

w2c согласен с формулировкой запроса:

- внешний клиент входит под именем и паролем пользователя консоли;
- живое видео он получает по праву смотреть камеру, архив — по праву смотреть архив;
- права те же, что в `Access`: роли, уровни объектов, папки.

## 3. Ограничение имени для RTSP

Решает владелец контракта. w2c удобнее вариант без ломающей правки — признак у пользователя «имя не годится для
RTSP». Причина: пользователи приходят и из каталогов (`AccessUser.catalogId`), и их имена консоль не выбирает.
Отказ при создании такого пользователя отрезал бы его от консоли целиком, хотя RTSP ему, может быть, не нужен.

## 4. Каких внешних клиентов имел в виду w2c

Не людей, а программы и устройства, которые сами держат поток:

- видеостена;
- сторонняя VMS или регистратор, который забирает потоки;
- облачный приёмник;
- программа аналитики.

Их пароль лежит в настройках чужой программы, поэтому w2c просил отдельную учётку. Обычному пользователю такого
клиента не хватает двух свойств. Третье уже есть:

1. **Только поток.** Пользователь не входит в консоль и в API, а только берёт видео. Если пароль утечёт из чужой
   программы, по нему нельзя ничего настроить. Права на камеры — по-прежнему через `Access`. Предлагаем признак у
   пользователя, например `AccessUser.streamOnly: true`. Имя и форму решает владелец контракта.
2. **Пароль от сервера, показанный один раз.** Пароль придумывает сервер, а не администратор. Консоль показывает
   его один раз — при создании и при смене, как сейчас `StreamAccountSecret`. Так он не совпадёт с паролем
   человека, и его не нужно хранить в консоли. Нужно для пользователей с признаком п. 1.
3. **Отключение без удаления.** Уже есть: `AccessUser.enabled`. Отдельного поля не нужно.

## Чего пока нет

- Решения владельца контракта по пунктам 1–3.
- Правки w2c на своей стороне (шлюз потоков). Её w2c делает после решения по пункту 4.
