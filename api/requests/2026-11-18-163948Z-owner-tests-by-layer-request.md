## 1. Тесты API идут по слоям

У каждого теста теперь есть слой:

- механизм (`mechanism`): то, что обязан делать каждый бэкенд;
- профиль (`profile:vms.camera/1` и другие): договорённость об одном профиле подсистемы;
- API видео (`video`): просмотр, запись, выгрузка.

Как читать отчёт:

- В начале строки теста стоит метка слоя: `PASS  [механизм] …`, `SKIP  [vms.camera/1] …`, `FAIL  [API видео] …`.
- В конце отчёта идут строки `LAYER`, по одной на слой: сначала механизм, затем профили по `id`, затем API видео. Пример: `LAYER vms.camera/1 1.0 — прошли 34, не прошли 0, пропущено 0`.
- Строка `LAYER <профиль> — не объявлен, пропущено N` значит: система профиль не объявила, его тесты пропущены. Это не провал.
- Тест профиля, которого система не объявила или чья версия ниже нужной, получает `SKIP` с причиной.

Что от w2c: готовность считать по строкам `LAYER`. Строка `LAYER механизм` без «не прошли» и строка каждого объявленного профиля без «не прошли».

## 2. Ответ на вопрос 2 вашей позиции: бэкенд без видео не получает тесты видео как сбои

Тесты видео пропускаются по операциям, которые система не объявила (`needs`, `capabilities.operations`). Бэкенд без видео получает `SKIP`, а не `FAIL`. Строка `LAYER API видео` у такого бэкенда — «прошли 0, не прошли 0, пропущено N»: это не провал.

Отдельного признака «API видео объявлен» пока нет: он появится после ответа на вопрос В2 (кто и как объявляет API видео). До ответа слой `video` отбирается по операциям.

## 3. Ответ про 39 сбоев `NO_ROUTE`

На стенде бэкенда тест, который вызвал операцию вне `capabilities.operations`, теперь не падает, а пропускается. Строка `SKIP` называет операцию: `система не объявила операцию X; тест не назвал её в needs`. На встроенном сервере и в петле тот же случай остаётся `FAIL` («…назвать её в needs»), так что ошибка теста не прячется.

Просьба к w2c:

1. Прогнать `tests/api.html?api=<стенд>` (или `python3 tools/check_stand.py <стенд>`).
2. Прислать имена тестов из строк «тест не назвал её в needs».

mockup допишет им `needs`, и они начнут пропускаться по условию, а не по вызову.

## 4. Как проверить себя по шагам

1. `tests/api.html?api=<стенд>&layer=mechanism` — только механизм. Должна быть строка `LAYER механизм — прошли N, не прошли 0`.
2. `tests/api.html?api=<стенд>&layer=mechanism,profile:vms.camera/1` — механизм и один профиль. Профили добавляйте по одному.
3. Полный прогон без `&layer=` — когда все слои, которые объявил бэкенд, прошли.

То же из командной строки: `python3 tools/check_stand.py <стенд> --layer mechanism,profile:vms.camera/1` (с `--layer` идёт только тест API, `?selftest` пропускается). Неизвестный слой или слой без тестов — отказ до прогона. При отборе слоёв строка «Каждая объявленная операция покрыта тестами» — `INFO`: покрытие считают только на полном прогоне.
