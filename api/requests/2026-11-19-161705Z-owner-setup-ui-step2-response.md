- Итог: права на операциях моста проверяет сервер — да. Закрытые операции сейчас не нужны ни страницам платформы, ни страницам VMS; условные потребности VMS — в п. 2.

## 1. Права на каждой операции моста

Да. Консоль платформы P/07 — фасад от имени человека. Каждая операция `read` сама отдаёт только то, что человек видит: публичную
проекцию по схеме вида. consolem права не пересчитывает — так и нужно.

Операции источника видов продукта (бэкенд VMS) P/07 передаёт от имени человека. Право на свои предметы источник проверяет сам.

## 2. Закрытые операции для страниц подсистем w2c

Страницам подсистем платформы из `BRIDGE_CLOSED` сейчас ничего не нужно. Когда понадобится, это будет только чтение своих видов
(`getUnit`, `listUnits` по своему `origin`). Подсистема пришлёт заявку: экран и зачем. Запись — только действиями P/07 от имени
человека. Закрытых операций записи через мост страницам не нужно.

Страницы VMS и плагинов psim:

Нынешний канон VMS не объявляет собственных страниц `iframe` с `setup/1`.
Потребность существующего экрана в API ещё не означает, что операцию нужно
открыть в мосте страницы настройки. Ниже перечисляем предметные потребности
по нормам, если соответствующие экраны будут встроены как свои страницы.
Каждая операция потребует отдельного запроса, когда экран действительно
перейдёт в iframe. Сейчас открытия моста не запрашиваем; обычной форме
плагина перечисленные операции автоматически не требуются.

|---|---|---|
| `startUnitLive`, `moveUnitLive` | «Просмотр» камеры; кадр для настройки зоны детектора, выбор сети доставки | V/11.15 N1.3, V/11.17 N1.2; живое видео остаётся закрытым в нынешнем мосте, нужен отдельный договор видео |

Для обычной страницы P/12 поля своего объекта покрываются шагом 1, чтение
связанных объектов, команды вида, переход и подписка — уже открытыми
возможностями шага 2. Для неё подтверждённого обязательного расширения
`BRIDGE_CLOSED` по нынешним нормам нет. Просмотр видео человеком на странице
плагина предусмотрен P/12.3-R015; если такая страница показывает камеры VMS,
ей нужен согласованный путь видео, а не машинные полномочия процесса плагина.

Запись правил, расписаний и режимов, вопросы правила, откат и повтор чужих
операций не просим открыть только потому, что они есть в старом V/11.
Штатные экраны consolem обслуживают их сами; общий цикл ассистента уходит
в P/07. Если потребуется своя страница редактора этих предметов, нужен
отдельный перечень с экраном и семантикой записи. `getSettings`, доступ,
сессия, ключи лицензий, служебные `/test/*` также не получают обоснования
для открытия обычной странице VMS или плагина. Права на `read` проверяет
сервер каждого маршрута; общую проверку 28 операций ведёт платформа.

## 3. API видео: та же разметка

Видеобайты отдают держатели `live`, `rec`, `exp`. P/07 выдаёт или проксирует
получение короткого токена `/where`; затем браузер идёт к держателю. Токен
нужен перед следующим требующим его запросом, отказ 403 требует нового
получения токена. Истечение токена не завершает уже начатый WHEP-сеанс;
повторный `/where` не продлевает этот сеанс.

При появлении согласованного описания API видео держателя разметку `x-bridge`
нужно рассмотреть по каждой операции этого описания: чтение, действие либо
закрытый доступ. Пишущий операторский запрос нельзя пометить `read` по его
HTTP-методу или спрятать в локальный запрос страницы. Карта моста consolem
должна получить отдельное описание видео и его адрес у объекта; нынешний
0.34.0 этого ещё не даёт. Нынешние двери WHEP и сегментов сами по себе не
являются готовой картой операций моста.

Для процесса плагина действует отдельный машинный договор P/12, не этот
браузерный мост. Его доступ к видео и право двери не подменяются правами
человека на странице. Согласие с направлением `x-bridge` не открывает
машинному процессу операторскую сессию.
