## Что мы делаем

Пользователь утвердил вид выбора нейросети у детектора. Это прототип 74: `index_74_fajl-nejroseti.html`, на Pages — https://ndm234234.github.io/consolem/index_74_fajl-nejroseti.html#node=30000027-0002-4000-8000-000000000000. В окне детектора на вкладке «Детектор» есть новые разделы:

- нейросетевой трекер → «Нейросеть»: стандартная нейросеть (что ищет: человек, человек сверху, машина, человек и машина; файл сервер подбирает по процессору) или свой файл `*.ann` на сервере детектора; процессор CPU, GPU NVIDIA или NPU Intel;
- трекер объектов → «Нейрофильтр»: включить и выбрать свой файл. Стандартного файла у нейрофильтра нет;
- выбор файла — список файлов, которые сервер нашёл в папке моделей, и пункт «Указать путь вручную…» с кнопкой «Проверить файл»;
- карточка выбранного файла: объекты, процессор, вход нейросети, размер и дата файла; ошибка у поля, если файл не работает на выбранном процессоре.

Это закрывает пробел CX2 в отчёте `docs/axxon-one-gaps.html`. В контракте этих полей нет. В прототипе всё сделано заглушкой: выбор, список файлов и проверка пути живут только в странице.

## Что нужно

Имена полей и путей — наше предложение. Владелец контракта может выбрать другие.

1. **Нейросеть детектора.** Свойство детектора `det`, например `neuralNet`, при `analyticsKind: neural`:
   - `standard` — что ищет стандартная нейросеть: `person` (по умолчанию), `personTop`, `vehicle`, `personVehicle`. В Axxon One это поле «Detection neural network»;
   - `file` — путь к своему файлу `*.ann` на сервере детектора. Пусто или нет поля — стандартная нейросеть;
   - `processor` — `cpu`, `gpu`, `npu`. В Axxon One это режим нейросети.
   - Зачем: без этих полей консоль не может сохранить выбор. Сейчас «Применить» оставляет его только в странице.
   - Что сломается: ничего, свойство новое и необязательное; без него детектор работает как раньше.
2. **Нейрофильтр трекера.** Свойство детектора, например `neuralFilter: {enabled, file, processor}`, при `analyticsKind: tracker`. Включённый нейрофильтр без файла сервер не принимает: 422 с `field` `/properties/neuralFilter/file`.
   - Зачем: в Axxon One нейрофильтр без файла не работает. Прототип блокирует «Применить» по тому же правилу; сервер должен держать его и без консоли.
3. **Список файлов в папке моделей сервера.** Чтение, например `GET /units/{serverUid}/neural-models`: `[{path, name, size, modifiedAt, processors?, classes?, input?}]`. Поля `processors`, `classes`, `input` — если сервер может прочитать их из файла.
   - Зачем: администратор выбирает файл из списка, а не вводит путь по памяти. Файл должен лежать на сервере детектора, а не на компьютере администратора.
4. **Проверка пути.** Действие, например `POST /units/{serverUid}/neural-models/check` с телом `{path}`: есть ли файл, формат `*.ann`, на каких процессорах работает. Ответ — то же описание файла, что в п. 3, или отказ с причиной (`notFound`, `badFormat`).
   - Зачем: кнопка «Проверить файл» у пути вручную. Без неё ошибка в пути видна только после запуска детектора.
5. **Несовпадение файла и процессора.** Если файл не работает на выбранном процессоре, сервер отказывает: 422 с `field` `/properties/neuralNet/processor` и списком процессоров файла в `params`.
   - Зачем: прототип показывает эту ошибку у поля и предлагает выбрать подходящий процессор.
6. **Сервер на Windows.** В Axxon One свой файл можно указать только у сервера на Linux. Нужен признак, например `capabilities.customNeuralFile` у сервера, или отказ на п. 1 с причиной.
   - Зачем: консоль должна показать запрет у поля, а не пустой список.

## Что не нужно

- Загрузка файла с компьютера администратора и библиотека моделей домена. Мы показали этот вариант пользователю, он выбрал список файлов на сервере.
- Нейросчётчик и детектор поз: их нет в макете. Когда они появятся, им подойдут поля п. 1.
