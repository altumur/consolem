# Запрос владельца контракта: своя страница подсистемы в iframe — что нужно со стороны w2c

2026-11-18 · контракт 0.23.0 · от владельца контракта (joynickray)

Кому: w2c

**Статус: отвечен** — [ответ w2c, 2026-11-18](2026-11-18-120707Z-owner-setup-ui-iframe-response.md)

Основа — [описание решения «Своя страница настроек подсистемы в consolem»](../../docs/contract-layers/2026-11-18-setup-ui-iframe-design.md)
и ответ на вашу позицию по слоям ([2026-11-18-114831Z-w2c-contract-layers-response.md](2026-11-18-114831Z-w2c-contract-layers-response.md)).
Подход вы приняли: страница подсистемы — только вид, правку настроек записывает consolem по «Применить» (или при уходе с карточки).

Этот запрос заменяет для w2c этап 2 из ADR-0115 §4.3 (`ready`, `height`, `dirty`, `saved`, `sandbox` без `allow-same-origin`,
запись страницей). Тот этап основан на п. 11 нашего прежнего запроса
[«Универсальная модель»](2026-11-03-065231Z-mockup-generic-model-request.md); его тоже заменяет описание решения.

Сторону контракта делает владелец: `setupUi.mode: iframe` с протоколом `setup/1`, новое `setupUi.protocol`, необязательное `origin`
у `setupUi` и `SetupUiLink`, адрес страницы `iframe` по праву `view`. Здесь — только то, что делает w2c.

## 1. `setup_ui[].mode: iframe` в манифесте

**Нужно.** В норме P/02.1 N1.2 (строки 167–176) `mode` — `tab` или `iframe`, умолчание `tab`. Бэкенд переносит `mode` в
`UnitKind.setupUi.mode`.

**Зачем.** Сейчас загрузчик отклоняет `iframe` (кейс `a115_setup_ui_mode_iframe`), и встроить страницу нельзя.

**Что сломается.** Ничего: `tab` остаётся умолчанием.

## 2. Страница `iframe` не пишет настройки

**Нужно.** Записать в норме: у страницы `mode: iframe` правку настроек объекта записывает consolem — `PATCH /units/{uid}` или
операция, бэкенд передаёт её подсистеме как правку строки объекта. Страница отдаёт правку consolem сообщением, сама в настройки
объекта не пишет. Свои пути сервера подсистемы (проверка связи, калибровка, свой график) страница по-прежнему зовёт напрямую,
но настройки объекта они не меняют.

**Зачем.** Журнал, откат, `If-Match` и права у правки страницы те же, что у любой правки в consolem.

**Что сломается.** Ничего у `mode: tab`: такая страница по-прежнему пишет сама (этап 1).

## 3. Ранг маршрута страницы и токен по настоящему праву

**Нужно.**

1. Маршрут `setup_ui[].route` страницы `mode: iframe` — с любым рангом, в том числе `view`. Сейчас — только `edit` или `admin`
   (строка 168).
2. Токен страницы выдаётся по настоящему праву человека на вид (`view`, `edit` или `admin`). Свои команды страницы дверь проверяет
   по рангу их маршрутов, как уже умеет (`door.routes: [{name, rank}]`).

**Зачем.** Страница `iframe` ничего не пишет, поэтому её видит и тот, у кого только просмотр. consolem передаёт ей `readOnly: true`.
Иначе у человека с просмотром был бы другой экран, чем у того, кто правит.

**Что сломается.** Ничего у `mode: tab`: там ранг остаётся `edit` или `admin`.

## 4. Встраивание: заголовки двери и оболочки

**Нужно.**

1. Дверь отдаёт страницу с `Content-Security-Policy: frame-ancestors <происхождение consolem>`. Чужой сайт страницу не встроит.
2. CSP оболочки consolem у w2c получает `frame-src` на происхождения дверей.
3. Страница работает в рамке `sandbox="allow-scripts allow-forms allow-same-origin"`, без `allow-top-navigation` и `allow-popups`
   (описание решения, раздел 5). `allow-same-origin` нужен, иначе `fetch` страницы к своей двери не работает — как вы отметили в
   ADR-0115, доп. 2, п. 8.

**Зачем.** Иначе страницу в рамке не показать или её может встроить чужой сайт.

## 5. Итоговое происхождение страницы

**Нужно.** Если двери или прокси перенаправляют страницу на другое происхождение, чем у выданного адреса, бэкенд называет итоговое
в новом поле `origin` (`setupUi.origin`, `SetupUiLink.origin`). Если не перенаправляют — поле не нужно.

**Зачем.** consolem принимает сообщения страницы только с ожидаемого происхождения. Без поля проверка не сойдётся.

## 6. Кука двери в iframe и запасной вход без куки

**Нужно.**

1. Двери стоят на других хостах, чем consolem, поэтому кука двери в рамке — `SameSite=None; Secure; Partitioned`, как вы
   предложили.
2. Проверить вход в браузерах, которые стороннюю куку в рамке не отдают даже с `Partitioned`. Прежде всего это Safari: там
   сторонние куки по умолчанию закрыты.
3. Если там вход не работает — запасной вход без куки: разовый ключ в пути адреса (`/t/<ключ>/…`) вместо `?t=`, а дверь держит
   сеанс по пути. Относительные `fetch` страницы psim тогда несут ключ сами, страницу переделывать не нужно.

**Зачем.** Без куки страница в рамке не обратится к своей двери, и экран будет пустым.

## 7. WebSocket страницы через дверь

**Нужно.** Дверь пропускает WebSocket страницы (как `/ws` у плагина `railway_detector` psim-sdk), с той же кукой или тем же
ключом из п. 6.

**Зачем.** Страница узнаёт о ходе своей работы (поиск, автодетектор) по WebSocket своего сервера.

## 8. Блоки формы из манифеста

**Нужно.** Бэкенд переводит `display.form` манифеста (блоки с заголовками, порядок полей) в расширения схемы `x-ui-tab`,
`x-ui-group`, `x-ui-order`. Они уже есть в контракте (`api/README.md`, раздел о `schema`).

**Зачем.** Форма по схеме — основной вид у вида без своей страницы и «Все параметры» у вида с ней. Без блоков она — плоский
список полей, на такой список пользователи жаловались.

**Что сломается.** Ничего: незнакомое `x-*` клиент пропускает.

## 9. psim-sdk

Протокол `setup/1` один для плагинов psim и для подсистем w2c. Библиотеку для автора страницы (`setup-bridge.js`) пишем мы, в
consolem, и предложим её авторам psim-sdk вместе со стороной consolem для эмулятора. Если вы ведёте разговор с авторами psim-sdk,
скажите — согласуем вместе.
