## 3. Что проверить

**Пункт 1. Имена и типы добавленных полей.**

| Вид / поле | Нынешняя трансляция VMS | Результат сверки |
|---|---|---|
| `storage.enabled` | обычный архив устройства — постоянное `true`; карточка w2c — `rec/volumes.enabled`, только чтение | Тип boolean совпадает; это не подтверждает остальной `vms.edge/1` |
| `storage.recordMode` | у обычного архива устройства поля нет; у карточки w2c — режим `always` или `backup` по `when` тома | Тип string совпадает там, где поле есть; общего набора режимов профиля не обещаем |
| `storage.short` | поля нет и у обычного устройства, и у карточки w2c | Тип string на выдаче не подтверждён; пустую строку вместо отсутствующего поля не вводим |
| `eventsrc.enabled` | `cam/cameras.enabled` | boolean — совпадает |
| `eventsrc.ip` | адрес из `source` | string — совпадает; для слушающего драйвера это адрес сервера или имя кассы |
| `eventsrc.model` | сегмент модели адреса `ipint://` | string — совпадает; собственного справочника кассового ПО не обещаем |
| `eventsrc.port` | порт адреса | integer — совпадает |
| `eventsrc.serverId` | UUID сервера, запись метки `server:<name>` | string/UUID — совпадает; это закрепление кассы за сервером |
| `eventsrc.short` | `cam/cameras.short` | string — совпадает |
| `eventsrc.vendor` | сегмент производителя адреса `ipint://` | string — совпадает |

Имена семи добавленных полей POS совпадают с нашей трансляцией, когда адрес
и запись дают соответствующее значение. Поле `model` у нас связано с адресом;
то, что экран его лишь показывает, не превращает его в новое поле хранения.
Это сверка норм, а не проверка ответов работающего backend.

Целый `vms.pos/1` пока не подтверждаем. Сейчас POS знает одну камеру `cameraId`,
`words`, задержку и длительность титров. Полная редакция профиля называет
дополнительные настройки, несколько камер с областями, разбор чеков и путь
`pos/raw`, которым нынешние нормы V/11 не дают полной трансляции. Совпадение
семи новых полей не устраняет этот предел.

**Пункт 2. `replicationStatus`.** Не можем подтвердить выдачу описанных восьми
полей: `state`, `lagSec`, `timeLeftSec`, `lastTransferAt`, `nextTransferAt`,
`bytesToday`, `gaps`, `cameras`. Их нет в нашей трансляции `storage`.
Для элементов `cameras` также не определены требуемые наблюдения. Наблюдение
задержки отдельной записи `replicaLagSec` и покрытие архива не являются этим
объектом состояния. Других эквивалентных имён, которые достаточно переименовать,
нормы не дают. Настройка `replication` полного профиля тоже не реализована
этой трансляцией. Поэтому сейчас `vms.edge/1` не объявляем; расширение —
только при отдельном согласовании норм и переходе.

**Пункт 3. Снятые поля acs.** Как на часть нового `vms.acs/1` на `login`,
`password`, `port` не опираемся. Нынешнее корневое соединение `acfa` может
иметь их в своей общей схеме, потому что это поля подключения устройства.
Пароль остаётся только входным секретом; чтение отдаёт признак установки,
а не значение. Вложенная единица СКУД таких реквизитов не имеет.
Снятие полей из особого экрана не означает удаление необходимых реквизитов
из общей схемы или разрешение читать секрет. Остальные ограничения состава
`acfa` и дочерних единиц сохраняются; полный профиль 1.1 требует сверки при переходе.
