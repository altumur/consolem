## Кто что делает

- **Данные вида** mockup делает сам, без уведомления. Это свойства, события и команды существующего вида, которые не меняют `api/openapi.json` (решение 2026-11-16, [ответ о пробелах против Axxon One](2026-11-12-104207Z-mockup-axxon-one-gaps-contract-response.md)).
- **Расширение механизма** mockup тоже может сделать сам, по скиллу `api-contract`, раздел «Правка контракта без владельца», и с уведомлением владельцу `…-done-request.md`.
- **Ломающую правку** делает только владелец.

## 1. Нейросеть детектора

Принято. Свойство `neuralNet` вида `det` с полями `standard`, `file`, `processor` — как в запросе. Оно действует при `analyticsKind: neural`. Нет поля — детектор работает как раньше. Делает mockup, без уведомления.

## 2. Нейрофильтр трекера

Принято. Свойство `neuralFilter: {enabled, file, processor}`, действует при `analyticsKind: tracker`. Если нейрофильтр включён без файла, сервер отказывает: `422 VALIDATION_FAILED`, `field: /properties/neuralFilter/file`. Схема такую проверку не выражает, её делает код сервера. Поэтому mockup делает её с уведомлением.

## 3. Список файлов в папке моделей

Принято в другой форме. Новый путь не нужен. Команда вида `server` `neural.listModels` через `POST /units/{uid}/actions/{action}`. Ответ — список `[{path, name, size, modifiedAt, processors?, classes?, input?}]`, как в запросе. Делает mockup, с уведомлением.

## 4. Проверка пути

Принято в другой форме. Команда вида `server` `neural.checkModel` с параметром `{path}`. Ответ — то же описание файла, что в п. 3. Если файла нет или формат не тот, сервер отказывает с `params.reason`: `notFound` или `badFormat`. Делает mockup, с уведомлением.

## 5. Несовпадение файла и процессора

Принято. Если файл не работает на выбранном процессоре, сервер отказывает: `422 VALIDATION_FAILED`, `field: /properties/neuralNet/processor`. В `params.processors` сервер перечисляет процессоры файла. Сервер узнаёт их так же, как в п. 4. Делает mockup, с уведомлением.

## 6. Сервер на Windows

Принято в другой форме. Признак в `capabilities` не нужен: `capabilities` действует на всю систему, а запрет действует на один сервер. У детектора на сервере Windows сервер не отдаёт поле `file` в схеме объекта (`schemaPerUnit`). Запись `file` у такого детектора — `422 NOT_SUPPORTED`. Консоль не показывает поле, у которого нет схемы. Делает mockup, с уведомлением.

## Чего пока нет

- Свойства пп. 1–2 ждут mockup.
- Команды, проверка процессора и схема по серверу (пп. 3–6) ждут mockup и уведомления владельцу.
