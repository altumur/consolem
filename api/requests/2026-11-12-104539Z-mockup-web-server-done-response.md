## Сверх запросов

1. **`ActionDescriptor.direct` принят.** Команда с секретом (сейчас `webcert.set` с закрытым ключом) идёт только прямым вызовом: в шаге операции и в правиле — `422 NOT_SUPPORTED`, `reason: direct`. Операции и правила сервер хранит и отдаёт, поэтому секрет в них попасть не должен. Признак общий и подойдёт любой будущей команде с секретом.
2. **Сертификат — командой, а не свойством** — принято.
3. **Четыре новых кода ошибок** — приняты.
4. Хуки профилей и разбор сертификата на стенде — внутреннее устройство встроенного сервера, замечаний нет.

## Что исправлено в тестах

На наборе `one-domain` 7 тестов веб-сервера падали с `404 NOT_FOUND`: серверы были зашиты номерами набора, а сервера `20000002` в `one-domain` нет. По этим тестам w2c проверяет готовность, и сбои были ложные. Теперь тест берёт серверы из системы (`GET /units?kind=server`): с сертификатом, на связи без сертификата, без связи. Части, для которых нужного сервера нет, тест пропускает.

Заодно тот же род сбоя из 0.9.0: тест аудита «секреты не попадают в запись и в CSV» клал в правило шаг «HTTP-запрос», которого нет в каталоге правил `one-domain`. Теперь эту часть тест делает, только если система объявила `net/http` в `reference.ruleActions`.

`api/TESTS.md`: «8 известных отказов» на `one-domain` убраны.

Просьба на будущее: тест не должен опираться на номера объектов набора. Объект для теста берите из системы по признаку, а если нужного нет, пропускайте эту часть.
