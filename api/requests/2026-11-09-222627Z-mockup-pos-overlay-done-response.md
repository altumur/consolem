## Схема возможностей драйвера

Поля, которые зависят от драйвера кассы (`terminalType`, `retalix` у POSLegacy, список типов терминала), не нужно описывать новой схемой драйвера. В модели для этого уже есть схема на объект: `schemaPerUnit` у вида и `GET /units/{uid}/schema`. Схема кассы зависит от её драйвера, условия — в `allOf`, как у параметров драйвера камеры. Тогда константы `POS_DRIVERS` и `POS_TERMINALS` уходят из `index.html`, и поля показывает форма по схеме. Это отдельная правка со своей версией, не срочно.

## Чего пока нет

- Схема на объект для кассы (см. выше). До неё список драйверов и типов терминала остаётся константами в `index.html`.
- Разбор данных (`parserFile`, `processing`…) на стенде — заглушка: сервер хранит и проверяет значения, но данных не разбирает.
- Титры в просмотре оператора рисует клиент просмотра. В консоли титры видны только в примере на карточке.
