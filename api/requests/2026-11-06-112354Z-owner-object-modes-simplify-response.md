## Что нужно

### П. 1. Приоритет по порядку строк — убран

Стрелок «выше — важнее» нет, порядок строк ничего не значит. Подпись страницы: «действует последнее переключение». Пересечения расписаний режимов — предупреждение над списком, например «Расписания режимов пересекаются: «Ночь» и «Выходной». В пересечении действует режим, который включился позже». Предупреждение видно всё время, а не только при сохранении: пересечение может появиться и от правки расписания в другом месте.

Расхождение: встроенный сервер по-прежнему считает `/modes/current` по порядку `items`. Интерфейс это не показывает, но в пересечении текущий режим пока выбирает порядок. Это ваша ломающая правка (см. «Вопросы», п. 1).

### П. 2. Строка «Иначе» — убрана

Режим по умолчанию — значение «По умолчанию» в столбце «Включается»; за ним стоит `otherwise`. Выбор «По умолчанию» у другого режима переносит `otherwise` на него и снимает у него расписание (`PUT /modes`). Если у режима по умолчанию есть и расписание (в `demo.json` это «Выходной»), под именем пометка «и режим по умолчанию».

### П. 3. «Сейчас» — одна строка

«Сейчас: Рабочее время, до 20:00 · Переключить… · Подробнее». После ручного переключения — «Сейчас: Ночь, вручную до 20:00». Полосы на неделю и календарь — под «Подробнее».

### П. 4. Режим в шапке, список — в «Расписаниях»

- В шапке консоли на любом экране — кнопка: цвет режима, его название и стрелка. Меню: «Переключить на «X»» для каждого другого режима, «Вернуть по расписанию: «Y»» (только после ручного переключения), «Режимы объекта…». Слово «Режим:» и «до 20:00» ушли в подсказку: при ширине окна 1440 px шапка их не вмещает.
- Режимы и текущий режим теперь читаются при старте (`GET /modes`, `GET /modes/current`), а не при входе в «Автоматизацию»: шапке они нужны сразу.
- «Режимы объекта» — ветка в «Расписаниях» рядом с «Особыми днями», а не отдельный раздел дерева. Вкладок у «Расписаний» нет — это ветка дерева, поэтому сделали так же, как «Особые дни».

### П. 5. Встроенных режимов меньше — ждёт сервера

В интерфейсе удалить нельзя только встроенные режимы: сервер отвечает 409 `BUILTIN` на любой из четырёх с `system`. Поэтому все четыре пока неудаляемые. Нужна ваша правка — см. «Вопросы», п. 3.

### П. 6. Столбцы — убраны

Столбцы: «Режим», «Включается», «Правила». «В меню оператора» нет. «Правила» — ссылка «N правил», она раскрывает список правил в строке; «нет правил», если правил нет.

Условие «Режим объекта» в правилах — как было: вернулось вместе с режимами.

## Вопросы

### 1. «Последнее переключение действует» — да

Согласны. Просим перевести на это API: `/modes/current` — по последнему переключению (расписание — в момент начала, оператор — в момент нажатия), `otherwise` — режим по умолчанию, порядок `items` без смысла. Как назвать поле по умолчанию и что делать с `otherwise` — на ваше решение; интерфейс подстроим.

### 2. Режим и переключатель в шапке — да

Сделано, см. п. 4.

### 3. Встроенных режимов — два

«Обычный» (режим по умолчанию) и «Обслуживание» (только вручную; неудаляемый — только он). Остальные — свои, кнопкой «+ Режим». Для демо в `demo.json` хорошо оставить «Ночь» своим режимом: на неё ссылается правило «Охрана входа ночью».

Нужно от вас: сервер — 409 `BUILTIN` только для `service`; `demo.json` — встроенные «Обычный» и «Обслуживание», «Ночь» и «Выходной» — свои.
