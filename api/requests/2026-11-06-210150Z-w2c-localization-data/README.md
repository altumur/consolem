# Полная опись границы w2c → consolem для локализации

Срез: VMS `6dccdcc8612a761fbf5c4fdc60de1504acc68c3c`, контракт consolem
`0fbdd125dcc976e871f7eea17f6b9538a81e7019` (0.2.0). Текущие таблицы и модель API перечислены полностью;
для будущих плагинов ниже указаны открытые семейства. Перевод источника w2c на английский идёт отдельно.

`currentText` и `currentLang` в приложении — фактические значения закреплённого среза, где ещё есть русские подписи.
Это контекст для проектирования таблиц, а не окончательный английский словарь. Целевые подписи и системные слова
w2c — английские; коды, ключи и пути при переводе подписей не меняются.

## 1. Виды объектов — весь текущий перечень

24 вида из `VMS/11-backend/data/kinds.json`:

| Группа | Передаваемые `kind` |
|---|---|
| Домен и инфраструктура | `domain`, `server`, `folder` |
| Камера и поток | `camera`, `stream` |
| Детектор | `det` |
| Устройства и их части | `ipsrv`, `channel`, `sensor`, `relay`, `mic`, `spk`, `storage` |
| Источник событий и СКУД | `eventsrc`, `acfa`, `acfa_sensor`, `acfa_lock`, `acfa_fence` |
| Архивы | `archive.local`, `archive.network`, `archive.backup`, `archive.edge`, `archive.incidents` |
| Том | `volume` |

Для каждого вида передаются `label`, при наличии `labelPlural`/`labelCount`, и описание схемы, возможностей,
действий и событий. Таблица перевода сопоставляет коду/стабильному ключу подпись интерфейса; само значение `kind`
в запросе и ответе остаётся прежним. Полные строки и источники — [kinds.tsv](kinds.tsv).

Виды плагинов и обычных таблиц подсистем образуют открытое множество: новые виды описываются манифестами
и приходят через тот же `/kinds`. Закрытого списка всех будущих плагинов нет. Для них действует та же схема
ключей, переводов и английского запасного текста.

## 2. Профили — весь текущий перечень

13 профилей:

`vms.domain/1`, `vms.server/1`, `vms.folder/1`, `vms.camera/1`, `vms.archive/1`, `vms.volume/1`,
`vms.stream/1`, `vms.detector/1`, `vms.acs/1`, `vms.live/1`, `vms.ptz/1`, `vms.talk/1`, `vms.timeline/1`.

Их `label` и подписи возможностей интерфейса локализуются; идентификаторы профилей и имена свойств не меняются.
Описание каждого профиля, наборы полей и предметных API — [profiles.tsv](profiles.tsv).

## 3. Все подписи и описания, приходящие с описанием вида

В срезе **503 позиции**: **316 значений `Text`** и **187 строковых подписей/описаний**.
У `Text` **181 уникальный ключ**; одинаковый ключ с разными текстами в срезе не найден.

Сюда входят:

- названия вида, единственное/множественное число и подпись с количеством;
- подписи профиля и класса доступа, подписи уровней прав;
- имена полей и подсказки — `x-label`, `title`, `description`, help;
- подписи вариантов — `x-enum-labels`;
- подписи вкладок, групп, единиц измерения — `x-ui-tab`, `x-ui-group`, `x-ui-unit`;
- названия действий, подтверждения команд, подписи параметров и результата команды;
- названия событий, подписи их параметров.

Все позиции с путями и имеющимися ключами — [descriptor-texts.tsv](descriptor-texts.tsv).
Это включает **311 позиций свойств**, считая вложенные поля и схемы команд/событий:
[kind-properties.tsv](kind-properties.tsv). У 128 из них нет `x-label.key`; среди них есть технические и
вспомогательные поля. Для тех, которые показываются человеку, нужно определить стабильный ключ/подпись,
а не полагаться на перевод произвольной строки имени поля.

Одиннадцать формальных мест использования `Text` в моделях API — [text-slots.tsv](text-slots.tsv):
`UnitKind.label/labelPlural/labelCount`, `Profile.label`, `ActionDescriptor.label/confirm.text`,
`EventDescriptor.label`, `AccessClass.label/levelLabels` и подписи дополнительных классов доступа.
Поля внутри `JsonSchema` приходят динамически и дополнительно покрыты описью описаний видов.

## 4. Действия, события, права и справочники

- **20 описаний действий и 16 описаний событий** у текущих видов — [actions-events.tsv](actions-events.tsv).
  Коды команд/событий, `execution`, `severity`, права и значения параметров — машинные данные; переводятся их подписи.
- **389 вхождений кодов метаданных**: виды/родители, профили, возможности, категории UI, классы/уровни прав —
  [descriptor-code-values.tsv](descriptor-code-values.tsv). Повторные вхождения показаны по месту использования.
- Каталог автоматизации: триггеры, действия системы и объектов, условия, управляющие шаги, способы запуска,
  области целей и варианты параметров. Все **108 вхождений кодов** из `rule-catalog.json` —
  [reference-codes.tsv](reference-codes.tsv).
- `Reference` также несёт режимы записи, типы служб/уровни поддержки, варианты экспорта, классы и уровни доступа,
  функции ролей и ограничения. Названия вариантов показываются словами интерфейса; их значения на проводе сохраняются.
- Справочник выгрузки несёт форматы, вид `video/frame`, компрессию, разрешение, поля титров, варианты защиты,
  назначения, режим одного файла. В `ExportReference.compression[].label` и `resolutions[].label` пока обычные
  строки, без `Text.key`: это отдельные места, для которых нужна схема перевода.

Марки оборудования, модели, имена шрифтов, имена драйверов и кодеки сохраняются как данные/технические названия;
переводятся подписи соответствующих полей и пояснения, если они нужны пользователю.

## 5. Значения состояний и перечислений

Полный каталог — [enums.tsv](enums.tsv): **600 вхождений enum-значений**, **322 разных значения** во всех
просмотренных моделях и описаниях видов. У каждой строки есть источник, путь и направление использования:
описание w2c, ответ w2c, иной ответ либо только входная форма/описание. Это не утверждение, что каждое значение
уже выдаёт работающий стенд; список охватывает объявленные варианты контракта.

Семейства:

- связь и условия объекта: `online/offline/unknown`, типы условий, `true/false/unknown`, причины;
- режимы записи, состояние записи, причина записи, виды детекторов и их настройки;
- роли сервера, типы устройств, СКУД/входов/выходов и их наблюдаемые состояния;
- операции и шаги: очередь, выполнение, итог, отказ, отмена, повтор/откат;
- правила: способы запуска, события, действия, условия, ветвление, состояния проверки, исполнения и ответа оператора;
- расписания, особые дни, режимы объекта, окна обслуживания;
- поиск устройств, сканирование/обход архива, доступность участков шкалы;
- отметки, удержания и результаты их проверки;
- выгрузка и её части, формат, качество, титры, защита и назначение;
- категории журнала, виды сообщений потока и ассистента;
- доступ, функции ролей, источники групп/каталоги и состояния синхронизации;
- лицензии и признаки возможностей системы.

Переводится представление значения в интерфейсе. Код остаётся прежним; подписи не записываются обратно вместо кода.

## 6. Отказы и результаты проверок

- **45 `ProblemCode`** — [problem-codes.tsv](problem-codes.tsv). Из них 37 названы в таблице отказов w2c;
  все **175 строк** соответствия дверей/статусов/полей — [refusal-codes.tsv](refusal-codes.tsv).
- `Problem.code`, `Problem.errors[].code`, ошибки групповой операции и ошибки `ExportCheck` требуют таблиц
  сообщений по коду и подстановкам. `field` остаётся именем/JSON Pointer и связывается с подписью поля.
- Вложенные проверки правил несут `params.issue {code, params}`. Семь явно перечисленных в контракте кодов —
  [documented-rule-issue-codes.tsv](documented-rule-issue-codes.tsv); остальные причины и параметры могут быть
  открытыми. Ключевые слова проверок схемы (`type`, `required`, `enum`, `readOnly`, `x-ref` и т. п.) тоже остаются кодами.

Перевод ошибки по свободному английскому `message` ненадёжен: для таблицы нужен стабильный ключ/код и параметры.
При неизвестном коде требуется английский запасной текст, а не потеря подробностей ошибки.

## 7. Строковые сообщения: где простой таблицы имён недостаточно

Нужно явно определить представление следующих полей:

- `Problem.message`;
- `RuleStatus.reason`, `ScenarioStatus.reason`;
- `UnitCondition.reason` вместе с `params`; наблюдаемые причины/`faultText` в `Unit.status.observed`;
- `TimelineUnavailable.reason`, `ArchiveFetchResult.refused[].reason`;
- `ExportGrant.refusal`;
- `Catalog.message`, `UserGroup.source.message`;
- `RuleMute.reason` — сначала отличить причину, введённую человеком, от системной;
- `JournalEvent.text`: системная фраза по `source/kind/fields` и исходный текст/данные журнала;
- `AssistEvent.text/summary/message`, `AssistChange.why`: шаблонный прогресс, сгенерированная реплика,
  вопрос и пояснение плана требуют разной политики. Произвольный ответ модели не является конечным словарём строк.

Команде предлагается определить, где достаточно существующего кода/`Text.key`, где нужен шаблон с параметрами,
а где текст остаётся содержимым сообщения и язык выбирается при его формировании. Менять контракт без отдельного
решения его владельца этим запросом не предлагается.

## 8. Данные, которые не являются словарём UI

Сохраняются без перевода: имена объектов/людей/ролей/групп/папок, пользовательские комментарии и тексты правил,
ввод оператора, значения произвольных строковых свойств, адреса/URL/пути, логины, id/uid/UUID,
ключи манифеста, JSON Pointer, коды и версии, токены, числовые/временные значения.
Секреты и `writeOnly`-значения не возвращаются; передаются только метаданные полей и признаки «задан».
Встроенная роль или встроенный объект может иметь локализуемую системную подпись по стабильному id;
это не разрешение переводить введённое пользователем имя.

## 9. Покрытие и открытые семейства

Проверены **179 компонентных моделей**, **115 схем тел ответов** внутри операций, **126 операций** контракта
(116 объявлено таблицей профиля w2c) и SSE-модели `StreamMessage`/`AssistEvent`.
**818 позиций строковых полей** перечислены в [schema-string-fields.tsv](schema-string-fields.tsv).
**610 строк** mapping с направлением поля — [mapped-fields.tsv](mapped-fields.tsv).
Значения `writeOnly` отмечены как входные, а не возвращаемые. Классификация строк автоматическая и служит
указателем для разбора: она не заменяет решение о смысле свободного текста.

**62 открытых объекта/словаря** — [open-payloads.tsv](open-payloads.tsv). В частности, произвольные свойства и
наблюдения объекта, схемы/значения плагинов, параметры события, результаты команды и подробности отказа.
Их будущие экземпляры не перечислить конечным словарём; опись закрывает места передачи, а схема локализации
должна задавать правило для новых ключей, видов и отсутствующего перевода.

Схемы операций и направление профиля — [operations.tsv](operations.tsv).
Хеши источников/таблиц, перечень достигнутых моделей и счётчики — [inventory.json](inventory.json).
Формальные ссылки на подписи — [text-slots.tsv](text-slots.tsv).
Проверка коллизий ключей — [caption-key-collisions.tsv](caption-key-collisions.tsv), сейчас ноль.

Опись воспроизводится [collect.py](collect.py), который читает только закреплённые Git-объекты:

TSV использует стандартное CSV-экранирование с разделителем TAB; все ячейки заключены в двойные кавычки,
включая пустые. Это сохраняет число столбцов без завершающих пробельных символов.

```sh
python3 collect.py --course /path/to/server-vms-course --consolem /path/to/consolem --out /path/to/inventory
```

Словарь платформенного модуля P/07 (519 слов) ведётся своей поставкой. Перечисленные здесь данные — граница
`backend`/consolem; словарь модуля не подменяет таблицы переводов этих данных в WebUI consolem.
