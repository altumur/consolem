## 1. Базовая форма у каждого объекта

Сделано. У объекта с ручным экраном в меню «Ещё» карточки и в меню строки дерева есть пункт «Все параметры». Пункт открывает форму по схеме вида (`baseFormHtml`). В форме все свойства схемы, вкладки по `x-ui-tab`. Сервер проверяет правку (`POST /units/validate`) до плана, как у незнакомого вида. Свойства сверх профилей вида отмечены «сверх профиля». В шапке формы есть «Режим для опытных» и кнопка «Вернуться к настройке».

Почему пункт меню, а не переключатель или вкладка. Обычная работа идёт в ручном экране, а все поля подряд нужны редко: интеграторам и видам плагинов. Кнопка на каждом экране путала бы пользователя. Это совпадает с вашим предложением в `docs/contract-layers/2026-11-16-kontrakt-i-podsistemy-predlozhenie.md`, пп. 6 и 10.

Как устроен черновик:
- Обе формы пишут в один черновик карточки. Правки «Все параметры» в плане — строки `PATCH /units/{uid}` с `properties`.
- Неприменённые правки живут в одной форме. Пока они есть в «Все параметры», вернуться к настройке нельзя. Пока они есть в настройке, «Все параметры» только для просмотра.
- Имя меняют только в настройке: ручные экраны пишут имя каждый по-своему.
- Поле, у которого на сервере нет значения, после очистки уходит из черновика. Консоль не шлёт `null`, иначе сервер снял бы секрет (`password`).

Вкладки «Дополнительно» больше нет: её свойства — в «Все параметры».

Где смотреть: `index.html`, функции `hasBaseForm`, `formAllCtxItem`, `baseFormHtml`, `xpropsVals`, `schemaDiffX`. Ссылка на форму: `index.html#node=<uid>&form=all`.

Как проверить:
1. Открыть камеру, «Ещё» → «Все параметры».
2. Изменить «к/с», нажать «Показать план» → «Применить».
3. `GET /units/{uid}` вернёт новое `fps`. Настройка камеры покажет то же значение.

## 2. Ручной экран — по профилю

Сделано. `screenType` выбирает экран по `implements` вида. К профилям экранов добавлены `vms.pos/1` (касса), `vms.edge/1` (встроенное хранилище) и `vms.talk/1` (динамик). Порядок задаёт консоль, а не порядок в `implements`: `vms.talk/1` — последний, поэтому вид с `vms.camera/1` и `vms.talk/1` получает экран камеры. Вид плагина с профилем получает тот же экран.

По коду вида экран выбирается только в двух случаях:
- У вида нет профиля в контракте: регистратор (`ipsrv`), канал, микрофон, датчик, реле, экспорт, почта, SMS. Профили для них не просим: экран по коду работает.
- СКУД: профиль `vms.acs/1` общий у четырёх экранов (`acfa`, `acfa_sensor`, `acfa_lock`, `acfa_fence`), поэтому один профиль не выбирает экран.

Вид со своей страницей плагина (`setupUi`) ручной экран не получает, даже если объявил профиль. Его форма — форма по схеме и кнопка «Страница плагина».
