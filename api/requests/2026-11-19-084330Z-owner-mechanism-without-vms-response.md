## 1. Механизм 0.32.0

Принято. Переходим сразу на текущую версию, без промежуточных. Консоль платформы P/07 сейчас описывает виды на 0.23.0 и перейдёт
отдельным этапом, по списку изменений вашей части 04.

Бэкенд VMS:

Переходить будем сразу с 0.2.0 на согласованную новую версию, без поддержки
промежуточных форм 0.26–0.31. Нынешний запрос разобран на 0.34.0; это ещё не
выбор пина. Переход одним срезом объединит договор источника P/07, регистрацию
видов и покрытия, устойчивые `uid`, версии и `If-Match` владельца, общий поток
со сбросом при недоказанной непрерывности, норму V/11, копию контракта с SHA,
сборку consolem и приёмку. Обслуживание сборки и адрес `consolem-api`
переходят к P/07. `assist/models` — предмет P/10, не источника VMS.

## 2. Что объявляет платформа, а что — бэкенд VMS

Да, состав верный. Одно уточнение: долю VMS даёт бэкенд VMS как источник видов, который платформа регистрирует по манифесту
продукта. consolem получает всё через платформу, одним `GET /kinds` и одним `GET /reference`. Отдельного адреса бэкенда VMS у
consolem нет (ответ на [015619Z](2026-11-19-015619Z-owner-tree-layouts-sections-response.md), п. 4).

Доля VMS:

Подтверждаем предметную границу: VMS отвечает за сборку камеры из `cam`,
`rec`, `det`, архивы, предметные пути VMS, свои справочники и проверки,
которые сможет исполнить. Платформа собирает это с другими источниками
в одном API P/07. consolem не обращается к отдельному API backend VMS.
Недоступность backend делает недоступной долю VMS, сохраняя работу платформы;
несовместимая версия договора источника должна дать отказ регистрации
и явно недоступные виды VMS.

По п. 2 вашего запроса справочники VMS должны находиться в описаниях наших
видов и ответах соответствующих предметных путей, а не в общей части
`Reference`. Это работа перехода: нынешний V/11.2 N1.5 ещё использует старые
места справочников. `record`, `safe`, `armed` — проверки backend VMS,
не механизма. Подтверждаем эту предметную принадлежность, но не готовую
трансляцию: нынешние нормы не задают `RuleCheck.safe`; форма — при репине
VMS на 0.34.0 в шаге 6 ADR-VMS-0007. Нынешние нормы задают условия
`recording` и `armed`. Точный каталог, его поля, результаты и перевод
в V/07 должны быть согласованы в шаге 6. Простая замена
имени `recording` на `record` этого не доказывает.

Нынешний каталог целей VMS содержит области `folder`, `server`, `domain`.
Предметный смысл выбора камер по серверу сохраняется.

## 3. Пути профилей: `vms.discovery/1`, `vms.scenarios/1`, `vms.relays/1`

По п. 3 принимаем направление адресации при переходе:

| Профиль | Новое место в API consolem | Что уже есть по нормам VMS |
|---|---|---|
| `vms.discovery/1` | `GET`, `POST`, `DELETE /units/{uid}/discovery` | поиск `cam/searches`, результаты `cam/found`, остановка; V/11.4 N1.9, V/01.8 |
| `vms.scenarios/1` | `GET`, `PUT /units/{uid}/scenarios`, `GET /units/{uid}/scenarios/status` | общий документ сценариев и состояние; V/11.4 N1.21, V/07.5 |
| `vms.relays/1` | `GET /units/{uid}/relays`, `GET /units/{uid}/relays/{name}` | чтение ретрансляторов домена; V/11.2 N1.2, V/11.3 N1.2a, `mapping.tsv` строки `Relay` / `RelayMember` |

В новом договоре профиль объявляется только у вида области, для которого
источник действительно обслуживает эти пути. Объект неподходящего вида —
`422 NOT_SUPPORTED`, указатель `/kind`; отсутствующий объект — `404 NOT_FOUND`.
Указатели ошибок тела — JSON Pointer, например путь элемента сценария.
Старые внешние `/domains/{domainId}/…` и их объявления в новом API снимаются.
Внутренние двери платформы с `/domain/…`, которыми пользуется источник,
не становятся из-за этого запрещёнными внешними путями consolem.

Новый адрес сам по себе не расширяет возможности: поиск сейчас ограничен
входным кластером, а сценарии зависят от общего документа домена и прав на него.
До объявления новых профилей нужно согласовать адресуемую область и перенести
пределы поиска и сценариев в новые ответы (`ipScanMax`, `kinds`, `maxItems`).
Неизвестный код включённого правила должен дать `422 NOT_SUPPORTED`
с `params.issue`; у нас такой общий принцип уже есть в V/11.2 N1.5,
а точные новые поля и указатели сверяются при переходе.
