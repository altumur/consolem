## Запрос о репликации, пункты 1–7

Пункты 1–7 приняты в том виде, в каком они лежат в `main`. Имена полей остаются как есть.

Пункт 1, прежний режим записи. Решение принято: выключение репликации и исключение камеры возвращают камере прежний режим записи и архив, а если прежнего нет, сервер ставит `always`. Это требование и к бэкенду: он хранит прежний режим сам, в теле объекта его нет. Так уже записано в `api/BACKEND.md`, профиль `vms.edge/1`.

## Дополнение об общем виде, пункты 1–4

Пункты 1–4 приняты. Вопросы дополнения закрыты:
- `archive-fetch` забирает и пропуски со встроенного хранилища (`edgeOrdered`), а с `edgeOnly: true` — только их. Отдельная команда `pull` не нужна.
- `segment.lost` приходит и тогда, когда устройство записало поверх записей раньше забора, с полями `from` и `to`. Отдельное событие не нужно.

## Сверх запросов

Приняты: связь встроенного хранилища следует за связью устройства, события из запуска правила идут в очередь (не больше 50, `allowChain: false` их не слышит), `replication` в `writable`, поведение стенда.

## Решения по вопросам владельцу

1. **Забор периода у регистратора.** Отдельный путь на всё хранилище пока не делаем: `archive-fetch` по каждой камере достаточно. Понадобится, если бэкенд VMS забирает записи с регистратора одной командой, — тогда отдельным запросом.
2. **Связь вернулась.** Стенд должен поднимать `device.restored`, когда связь камеры вернулась (`device.signal`): событие объявлено, и шаблон «Связь вернулась: забрать пропуски с карты» должен срабатывать без `POST /test/events`. Это правка сервера, контракт не меняется. Сделайте её отдельным коммитом и уберите пункт из «Чего пока нет» в `api/BACKEND.md`, если он там есть.

## Чего пока нет

Список из уведомления остаётся без изменений: срок хранения карты, `bytesToday` по камере регистратора, один забор на хранилище, связь хранилища с правилами, тексты карточек типов, событие `replication.started`. По каждому пункту — отдельный запрос, когда он понадобится.
