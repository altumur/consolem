# События детекторов `abandoned`, `disappeared`, `crowd` в правилах

- Дата: 2026-11-03
- Команда: `mockup`
- Коммит контракта: `9818b3b`
- Статус: новый

Детектор этих видов можно создать, а правило по его событию контракт описать не даёт. Нашли в прототипе 18: администратор создаёт детекторы «Оставленный предмет» и настраивает правило по их событию.

## 1. Объявить события этих видов в правилах

**Что нужно.** Добавить в `reference.ruleTriggers` виды `det/abandoned`, `det/disappeared`, `det/crowd`, цель — камера. Коды уже есть в `Device.detectorKind` и `reference.eventKinds`.

**Зачем.** Сейчас объявлены только `det/motion`, `det/linecross`, `det/lpr`, `det/other` (`api/fixtures/demo.json`, `api/rule-engine.js:22-25`). Включённое правило с `det/abandoned` получает `422 NOT_SUPPORTED`, `trigger.notDeclared`. Поэтому интерфейс не может предложить событие детектора, который только что создал. Прежняя форма записывала `det/other` с пустым `match`: такое правило сработает на любой другой вид.

**Другой вариант, если свои виды не подходят.** Описать в контракте поле `detectorKind` события `det/other`, чтобы работало `match: {detectorKind: "abandoned"}`. Сейчас сервер такое правило принимает, потому что ключи `match` открыты. Но контракт нигде не говорит, что событие детектора несёт это поле.

**Что сломается.** Ничего: новые значения в справочнике, старые правила остаются.

**Как проверено.** Живые вызовы на встроенном сервере, коммит контракта выше:

| Правило, `enabled: true` | Ответ |
|---|---|
| `det/abandoned`, `match: {}` | `422 NOT_SUPPORTED`, `trigger.notDeclared` |
| `det/other`, `match: {detectorKind: "abandoned"}` | `201` |
| `det/other`, `match: {template: "tmpl.abandoned"}` | `201` |
| `det/other`, `match: {}` | `201` |

Нашли и другое место с этими кодами: `reference.scenarioKinds`, `ScenarioWhen.kind`. Это отдельный документ, `BACKEND.md`, сценарии: «Отдельно от `Rule`», встроенный сервер его хранит и не исполняет. Для правил он не подходит. Цель правила — запись детектора, а не камера: сервер это принимает, но `ruleTriggers[].deviceTypes` говорит «камера или вход», а вид события остаётся необъявленным.

Пока прототип ставит для них `det/other` с `match.template`, но это наша догадка.

## 5. Поле, которого нет в событии

**Что нужно.** Сверить `api/rule-engine.js:635` с контрактом.

**Зачем.** `RuleTrigger.match` говорит: «Поля нет в событии — не совпало». Код `eventChecks` считает отсутствие поля совпадением: `(e.match || {})[m] === undefined`. Поэтому `POST /rules/test` с `match: {detectorKind: "abandoned"}` и событием с пустым `match` даёт `event.came`, а с `detectorKind: "crowd"` — `event.other`. Тест `tests/api-automation.js:135-140` проверяет только поле со значением. Другие пути сравнения мы не проверяли.

**Что сломается.** Правила и тесты, которые опираются на нынешнее поведение. Если ошибка в тексте контракта, поправьте текст.
