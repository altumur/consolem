### П. 5. Клиент и незнакомая версия

Консоль знает профили той версии, под которую написаны её ручные экраны: раздел `profiles` набора demo в `api/fixture.js`. Его собирает `tools/build_api.py` из `api/profiles/*.json`. Версию сервера консоль берёт из `GET /kinds` → `profiles[].version`; без `version` — `M.0` по номеру в `id`.

Сделано в `bb3b456` (перенос из прототипа 82), описание — `CHANGES.md`, раздел «Версия профиля от сервера — из прототипа 82».

1. **Младшая версия выше известной — сделано.** Поле, которого консоль не знает, не входит в поля особого экрана. «Все параметры» показывают его с меткой «новое в версии профиля 1.7», шапка формы объясняет метку. Метки нет, если версия сервера не выше знакомой (лишнее поле той же версии — «сверх профиля», как раньше), если версия не по формату `M.m` и если поле приносит другой знакомый профиль того же экрана.
2. **Младшая версия ниже известной — сделано частично.** Поле, которого нет в версии сервера, не входит в поля особого экрана: «Все параметры» и счёт покрытия это учитывают. Но сам особый экран поле не прячет. Замер прототипа 82: из 116 полей, которые рисуют ручные экраны, 86 экран рисует и без поля в схеме вида, прячет 4, 26 замер не проверил (у объекта замера этих полей нет). Чтобы экран прятал поле, нужна общая проверка поля во всех ручных экранах. Это отдельная работа mockup.
3. **Незнакомая старшая версия — было и раньше.** Консоль пропускает профиль и открывает объект формой по схеме (`PROFILES_KNOWN`, часть 07 плана).
