## Зачем

На экране «Автоматизация → Режимы объекта» в прототипе 32 (`index_32_rezhimy-i-osobye-dni.html`) много всего: приоритет по порядку строк, строка «Иначе», цвета, полосы на сутки, столбцы «В меню оператора» и «Правил», четыре встроенных режима, которые нельзя удалить. Пользователь не понимает, чем режимы отличаются от расписаний.

Понятие нужное. Расписание отвечает на вопрос «действует ли сейчас», а режим — это одно имя состояния объекта, которое **оператор может переключить вручную** («Обслуживание», внеплановый выходной). Но в отрасли его делают намного проще:

| Продукт | Как устроено |
|---|---|
| Milestone XProtect | Режимов нет: профили времени в правилах, ручное — пользовательское событие (кнопка оператора) |
| Genetec Security Center | Расписания + «уровень угрозы»: короткий список, включают только вручную |
| Hikvision / Dahua | Расписание охраны у детектора; сцены «Дома / Ушёл / Сон»: включают кнопкой или по расписанию, действует последняя |
| Verkada, Eagle Eye | Охрана вкл/выкл: по расписанию и переключателем в шапке |
| SmartThings, Ring, Home Assistant | Modes: 2–4 режима, текущий виден в шапке, переключают автоматизации или человек, «последнее переключение действует» |
| Охранные панели (Bosch, Ajax, Болид) | Взятие / снятие: 2–3 состояния, вручную и автовзятие по времени |

Общее у всех: режимов мало; текущий режим и переключатель на виду; приоритетов нет — действует последнее переключение; связь «расписание включает режим» задают одним полем.

## Что нужно

1. **Убрать приоритет по порядку строк** (стрелки «выше — важнее»). Модель — «последнее переключение действует»: расписание переключает режим, когда начинается, оператор — когда нажал. Пересечения расписаний — предупреждение при сохранении.
2. **Убрать строку «Иначе»**: режим по умолчанию — первый в списке (или одно поле «по умолчанию»).
3. **Свернуть «сейчас» до одной строки**: «Сейчас: Ночь, до 08:00» и «Переключить…». Полосы на сутки и цвета — под «Подробнее» или в карточке расписания.
4. **Текущий режим и переключатель — в шапку консоли**, как у SmartThings и Genetec. Список режимов — вкладка рядом с «Расписаниями», а не отдельный раздел дерева.
5. **Меньше встроенных режимов**: с самого начала только «Обычный» и «Обслуживание». Неудаляемым оставить только «Обслуживание». Остальные добавляют кнопкой «+ Режим».
6. **Убрать столбцы**: «В меню оператора» — у всех режимов по умолчанию; «Правил» — ссылкой в строке.

Минимальный вид:

```
Шапка:  [ Режим: Обычный ▾ ]   → «Переключить на… Обслуживание / Ночь»

Автоматизация → Расписания → вкладка «Режимы»
  Режим          Включается                     Правил
  Обычный        по умолчанию                   12
  Ночь           «пн–вс 20:00–08:00»  Изменить  5
  Обслуживание   только вручную                 3
  [+ Режим]
```

Условие «Режим объекта» в правилах остаётся как есть.

## Что сломается

- Пп. 1–3, 5–6 можно сделать только в интерфейсе прототипа: контракт не меняется, порядок `items` и `otherwise` в `/modes` просто не показываются.
- Если и в API перейти на «последнее переключение действует», `otherwise` и порядок `items` в `/modes` теряют смысл, а `/modes/current` считается иначе. Это ломающая правка: её сделает владелец отдельно, после того как договоримся по интерфейсу.
