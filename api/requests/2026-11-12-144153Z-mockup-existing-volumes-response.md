## 1. Поле тома «подключить с записями»

Принято.

- `attachExisting` — свойство вида `volume` с `x-transient`, как `confirmShrinkBytes`. Сервер судит его в `POST /units`, но не хранит и не отдаёт.
- С `attachExisting: true` сервер подключает том как есть и не форматирует его. Том получает `state: ready` (или `open`, пока сервер читает индекс), а не `unfmt`.
- Без поля сервер работает, как раньше.
- Новых кодов отказа нет. Если по адресу нет тома с записями или тип тома не подходит хранилищу, сервер отвечает общим `422 VALIDATION_FAILED`, `field: /properties/attachExisting`. Причину сервер называет в `params.reason`, например `notFound` или `storageMismatch`.

Кто делает: mockup, с уведомлением владельцу. Это новое поведение сервера: он не форматирует том и проверяет адрес.

## 2. Найденные тома

Это команда вида: сервер по ней ищет тома на дисках и в папке NAS. Команда что-то делает, а не только хранит значение, поэтому mockup делает её с уведомлением.

- Это команда вида хранилища со `scope: ["kind"]`, как `probe` у камеры. Клиент вызывает её через `POST /kinds/{kind}/actions/{action}`: хранилища ещё нет. Новый путь не нужен.
- Параметры и результат mockup описывает схемой команды в `actions`.
- На тестовом стенде сервер может отдавать готовый список из набора. Сканировать диски по-настоящему стенду не нужно.

## 3. Период записей у тома
