## Что мы сделали

Этот запрос сообщает, что мы сделали по [ответу на запрос о мета-детекторе и семействах детекторов лиц](2026-11-16-142236Z-mockup-meta-detector-face-families-response.md), пп. 5–6. Сам [запрос](2026-11-16-142236Z-mockup-meta-detector-face-families-request.md) оставляем как есть. Пп. 1–4 вошли в контракт 0.17.0 как данные вида.

Коммит `40a277b` («API: mockup — несовместимые виды серверных детекторов на одном сервере (reference.analyticsConflicts); контракт 0.21.0»). Версия контракта — 0.21.0: номера 0.19.0 и 0.20.0 заняли правки, которые пришли в `main` раньше (файлы ассистента, ключи лицензий). Мы добавили ключ справочника и новую проверку сервера. Мы ничего не сняли и не переименовали. Описание — `api/README.md`, раздел «Что добавлено в 0.21.0», и `api/BACKEND.md`, строка «Несовместимые виды серверных детекторов (с 0.21.0)».

## Что проверить

1. **П. 5, таблица несовместимости.** Ключ `reference.analyticsConflicts`: массив `{analyticsKind, conflicts: [...]}`, по образцу `detectorOptions[].conflicts`. Связь двусторонняя: достаточно строки у одного из видов.
   - В наборе: `faceTV` — с `faceVA` и `faceVL`, `faceVA` — с `faceVL`.
   - Таблица касается только серверных детекторов: `detectorKind: other`, без `builtin`.
2. **П. 5, отказ.** Сервер не создаёт и не включает детектор, если на том же сервере включён детектор несовместимого вида.
   - Ответ — `409 BUSY`, `params: {reason: "incompatible", with: [uid…]}`.
   - `field` — `/properties/enabled` при включении и `/properties/analyticsKind` при создании.
   - Шаг операции — `fail BUSY` с теми же `params`.
   - Выключенный детектор создаётся без проверки.
3. **П. 6, охват — сервер детектора.** Сервер детектора — его `serverId`, а без него сервер камеры. Детекторы разных пакетов на разных серверах работают.
   - Документы Axxon One 3.0 говорят «You cannot install several packs in the same system»: 592299 (Face detector TV), 590799 (Face detector VA), 282770 (Face detector VL).
   - Мы читаем «system» как компьютер, а не как всю систему Axxon One. Пакет — это add-on DetectorPack: его ставят и удаляют на компьютере через «Apps & Features» (282780, переход с детектора лиц TV на VA). Установщик второго пакета отказывает на этом компьютере: Jira ACR-75635 (запись реестра `HKEY_LOCAL_MACHINE\SOFTWARE\AxxonSoft\Addons\DetectorPack\FaceRecognitionPack`) и ACR-77473 («VA Face Recognition Pack is already installed»).
   - Прямой фразы «один пакет на сервер» в документах нет. Живой сервер Axxon с двумя серверами и разными пакетами мы не проверяли.

Тест — `tests/api-devices.js`, «Несовместимые виды серверных детекторов (с 0.21.0)…».

## Сверх запросов

- **Смена вида и сервера.** Правка включённого детектора, которая меняет `analyticsKind`, `detectorKind` или `serverId` на несовместимый, тоже получает `409 BUSY`; `field` — изменённое поле.
- **Перенос камеры.** `PATCH` камеры с новым `serverId` получает `409 BUSY`, `field: /properties/serverId`, если её включённый детектор встретит на новом сервере детектор несовместимого вида.
- **Новая камера с детекторами в одной строке `POST /units`.** Сервер детектора — `serverId` новой камеры. Соседние строки той же камеры тоже считаются: два пакета в одной строке дают отказ второму детектору. У соседа ещё нет `uid`, поэтому `with` пуст.
- **`with` — массив.** У встроенных детекторов `with` по-прежнему строка (`conflictParams`). Консоль принимает оба вида. Описание кода `BUSY` в `openapi.json` называет оба.
- **Интерфейс.** Таблица идёт из справочника (`detAkClashSet`), а не из константы страницы. Плашка окна детектора, переключатель, групповое «Включить» и мастер «Добавить детекторы» считают только детекторы того же сервера. В мастере вид лиц больше не выключен целиком: причину «мешает «Лица VA»» показывает камера того сервера, где уже работает другой пакет.

## Чего пока нет

- **Сервер камеры через архив.** Встроенный сервер находит сервер камеры только по `serverId`, а интерфейс — ещё и по архиву записи. В наборе у каждой камеры есть `serverId`, поэтому разницы нет.
- **Камера меняет сервер через архив записи.** Отказ при переносе проверяет только прямую правку `serverId` камеры.
- **Профиль `one-domain`.** У вида `det` там нет `analyticsKind`, поэтому новый тест пропускается.

## Что сломается у тех, кто уже работает по контракту

Это новая проверка для значений `faceTV`, `faceVA` и `faceVL`, которые есть с 0.17.0. Клиент, который включал два детектора лиц разных пакетов на одном сервере, теперь получит `409 BUSY`. Так решил владелец в ответе, п. 5. Других изменений нет.

## Что решить владельцу

- Принять охват «сервер детектора» с доводами п. 3 или назвать другой.
- `with` массивом для серверных видов и строкой для встроенных: оставить так или вести оба к массиву (ломающая правка для встроенных).
