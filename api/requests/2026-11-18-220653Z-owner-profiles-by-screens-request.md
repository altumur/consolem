## 1. Что мы сделали

- `vms.acs/1`, версия `1.1`. Сняты `login`, `password`, `port`: карточка и мастер СКУД их не показывают. Запись `changes` с `removed`.
- `vms.edge/1`, версия `1.1`. Добавлены `enabled`, `recordMode`, `short`: вкладка «Хранилище» их показывает. У поля состояния `replicationStatus` описаны внутренние поля (`state`, `lagSec`, `timeLeftSec`, `lastTransferAt`, `nextTransferAt`, `bytesToday`, `gaps`, `cameras[]`). Тип поля прежний (`object`), `required` и `additionalProperties: false` не добавлены.
- `vms.pos/1`, версия `1.1`. Добавлены `enabled`, `ip`, `model`, `port`, `serverId`, `short`, `vendor`: карточка кассы их показывает.

## 2. Что это значит для вас

- Снятые поля `login`, `password`, `port` у вида СКУД можно больше не переводить под нашим именем. Отдавать их дальше не запрещено: экран их не читает, «Все параметры» их покажут.
- Добавленные поля экран показывает, если вид их отдаёт. Если бэкенд их не отдаёт, экран работает без них.
- Бэкенд отдаёт `version` из файла профиля. Консоль с профилем `1.0` продолжает работать: новые поля она показывает в «Все параметры».
- Объявленный `vms.acs/1`, `vms.edge/1`, `vms.pos/1` остаётся в силе, новые старшие версии не нужны.

## 3. Что проверить

1. Для видов, которые вы объявили с этими профилями, имена и типы добавленных полей совпадают с файлами профилей (`api/profiles/vms.edge.json`, `api/profiles/vms.pos.json`).
2. `replicationStatus` у вас отдаёт поля, которые описаны в `vms.edge.json`, с теми же именами. Если у вас другие имена, напишите ответ: эта правка только добавила описание.
3. Вы не опираетесь на снятые поля `vms.acs/1` как на часть профиля.
