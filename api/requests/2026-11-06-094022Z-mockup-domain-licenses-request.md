# Запрос от команды mockup: лицензии по доменам и опции домена

2026-11-06 · коммит контракта `7470a05` (0.2.0) · от команды mockup, для владельца контракта

Кому: владелец контракта

**Статус: новый**

## Что мы делаем

Мы переделываем раздел «Опции» по образцу Axxon One и добавляем страницу «Лицензии по доменам». Страница показывает несколько доменов сразу, как дерево «Оборудования»: один домен или все домены по переключателю в шапке. Сейчас `GET /licenses` отдаёт одно число на всю систему (`kind`, `used`, `total`), без домена. Поэтому страницу по доменам нельзя построить по контракту.

## Источники

Axxon One 3.0, документы Lexiro: 291981 («The Domain object»: серийный номер, срок, «Total devices created: N. Allowed in key file: M», счётчики функций по серверам, «Computer/key HID mismatch», «License feature owners»), 590781 и 283277 (типы лицензий и пределы, предупреждение за 30 дней), 291476 (лицензия действует на все серверы домена), 291504 (Cross-System client: опции домена повторяются для каждого домена). Живого сервера Axxon мы не проверяли.

## Что нужно

Имена полей — наше предложение. Владелец контракта может выбрать другие.

1. **Лицензия каждого домена.** Например, `GET /domains/{domainId}/license` или поле `domainId` в элементах `GET /licenses`. Поля:
   - `serial` — серийный номер (сейчас он есть только как свойство домена `license`);
   - `product` — тип: `demo`, `free`, `start`, `professional`, `enterprise`, `unified`;
   - `expiresAt` — срок действия (UTC) или `null`, если срока нет;
   - `state` — `active`, `expiring` (осталось 30 дней и меньше), `expired`, `mismatch` (ключ не совпал с компьютером), `missing`;
   - `stateText` — текст ошибки сервера, если он есть (как «Computer/key HID mismatch» в Axxon One);
   - `features` — список счётчиков: `code` (`cameras`, `acfa`, `faceSearch`, `lpr`…), `used`, `total` (`null` — без предела), и разбивка `servers: [{serverId, used, total}]`.
   Зачем: Axxon One показывает это у объекта «Домен» (документ 291981). Без этих полей оператор не видит, в каком домене кончились лицензии.
2. **Кто занимает лицензию.** Способ получить объекты, которые используют функцию лицензии в домене: например, фильтр `GET /units?licenseFeature=faceSearch&domainId=…`, или список `owners` в счётчике. Зачем: в Axxon One это группа «License feature owners». Оператору нужно знать, что выключить, чтобы освободить лицензию.
3. **Домен без связи.** Для домена с `link: offline` — последние известные данные и время, когда сервер их получил (`observedAt`). Иначе страница не может сказать «данные на 10:40», и пустое место выглядит как «лицензий нет».
4. **Опции домена.** Сейчас `GET /settings` — одна запись на систему. В Axxon One опции домена (хранение, тревоги, PTZ, политика безопасности, NTP и другие) свои у каждого домена (документ 291504). Нужен ответ: опции — общие на систему или у каждого домена свои? Если свои — `GET/PATCH /domains/{domainId}/settings` с тем же `If-Match`. Новые поля опций мы пришлём отдельным запросом, когда вид раздела утвердят.
5. **Событие в потоке.** Изменение лицензии домена — событие с новой версией, как у `settings`. Тогда страница обновляется сама после активации ключа.

## Уточнение от 2026-11-06: один ключ на несколько доменов

Пункт 1 исходит из правила «у каждого домена свой ключ». Это правило неполное. Ключ Axxon One действует на один домен или на несколько; домены одного ключа берут лицензии из общего пула. Поэтому в пункт 1 добавляем:

1а. **Ключ — отдельный объект, домены ссылаются на него.** Например, `GET /licenses/keys` со списком ключей. У ключа — `id`, поля пункта 1 (`serial`, `product`, `expiresAt`, `state`, `stateText`, `features`) и `domainIds` — домены, на которые он действует. Счётчик `features[]` — по пулу ключа (`used`, `total`), с разбивкой `domains: [{domainId, used}]`; разбивка по серверам — внутри домена. У домена — ссылка на его ключ (`licenseKeyId`). Зачем: интерфейс показывает карточку на ключ, в ней домены ключа и долю каждого домена в пуле. Без `domainIds` интерфейс не отличит общий пул от двух отдельных ключей и покажет неверный запас.

Предложение `GET /domains/{domainId}/license` из пункта 1 тогда не нужно: домен находит свой ключ по `licenseKeyId`. Пункты 2, 3 и 5 относятся к ключу так же, как к домену; для п. 3 — `observedAt` у каждого домена пула, ведь один домен пула может быть без связи.

## Уточнение от 2026-11-06: лимиты доменов и действия с ключом

Прототип 32 (раунд 3) показывает лимиты доменов в общем ключе, мастер ключа и снятие домена с ключа. Для них в API нужно:

1б. **Лимит домена в общем ключе.** В разбивке `features[].domains[]` — поле `limit`: сколько лицензий функции домен может взять из пула, не больше; `null` — без ограничения. Лимит — потолок, не резерв: свободные лицензии сверх лимита остаются другим доменам. Сумма лимитов может быть больше пула. Нужен ответ: что сервер делает с устройствами домена сверх нового лимита — выключает сразу, даёт льготный срок или оставляет до перезапуска? От ответа зависит текст предупреждения в мастере.

1в. **Действия с ключом**, у каждого — `If-Match` и событие из п. 5:
   - добавить ключ: файл ключа или серийный номер, затем активация; в ответе — что сервер прочёл из ключа (тип, срок, `features[].total`), чтобы мастер показал это до назначения доменов;
   - назначить ключ доменам и задать лимиты одним запросом: `domainIds` и `limits: [{domainId, feature, limit}]`. Домен с другого ключа при этом уходит с прежнего ключа; одним запросом — чтобы домен не остался без лицензий между двумя вызовами;
   - снять домен с ключа — один домен или все домены ключа сразу. Ключ без доменов остаётся, его можно назначить снова; домен без ключа получает `state: missing`;
   - удалить ключ. Его домены остаются без ключа (`state: missing`), их устройства и настройки не трогаются. Добавлено 2026-11-06 (прототип 32, раунд 4).

   Зачем: мастер «Ключ → Домены → Лимиты → Проверка» и кнопка «Снять с ключа» в карточке ключа. После снятия интерфейс 10 секунд предлагает «Отменить». Нужен ответ: отменять повторным назначением с прежними лимитами, или сервер откладывает снятие на время отмены?

## Что сломается

- Если `GET /licenses` получит `domainId` и строку на каждый домен, старый клиент (`index.html`, `licenses.find(l=>l.kind===k)`) покажет число первого домена вместо суммы. Отдельный путь (`/domains/{domainId}/license`) этого не ломает.
- Пункт 4: если опции станут доменными, `PATCH /settings` у тех, кто уже работает по контракту, перестанет менять опции всех доменов сразу.
