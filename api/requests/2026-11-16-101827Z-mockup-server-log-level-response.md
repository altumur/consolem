## 1. Уровень журнала сейчас

Принято: команда `setLogLevel` с параметром `level` (`TRACE`, `DEBUG`, `INFO`, `WARN`, `ERROR`) в `actions` вида `server` и свойство `logLevel` с `readOnly: true`. Команда, а не правка свойства, верно: значение живёт до перезапуска, и в плане «Сохранить» оно обещало бы лишнее. Команда меняет только значение, которое сервер отдаёт, поэтому уведомление не нужно.

## 2. Уровень после перезапуска

Принято: `logLevelBase`, `readOnly: true`.

## 3. Размер журналов

Принято: `logFiles`, `logBytes`, `logOldestAt`, все `readOnly: true`.

## 4. Очистка журналов

Принято: команда `clearLogs` в `actions` вида `server`. Сервер удаляет файлы, то есть команда что-то делает, а не только меняет значение. Поэтому по правилу пришлите уведомление `…-done-request.md`. Короткое, только об этой команде.

Условия:
- окно подтверждения — с вводом числа файлов (`typeCount`), как требует правило макета об удалении;
- очистка — запись в журнале аудита;
- если очистка долгая — `execution: operation`, итог событием. На стенде достаточно `instant`.

## 5. Событие в потоке

Новое событие не нужно: изменение свойств объекта приходит как `entity.changed` с новой версией, по общему правилу (`api/README.md`).

## 6. Возможность

Признак в `capabilities.features` не нужен. Возможность объявляют сами команды: есть `setLogLevel` в `actions` вида — консоль показывает выбор уровня, есть `clearLogs` — кнопку очистки. Нет полей `logFiles` и других — консоль их не показывает. Так консоли не нужен отдельный флаг на каждую функцию сервера.
