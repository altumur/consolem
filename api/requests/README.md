# Запросы к API от команд VMS

Здесь лежат запросы команд, которые делают бэкенд конфигуратора за своей VMS, и наши ответы. Один запрос — один файл `…-request.md`, ответ на него — отдельный файл рядом с тем же началом и `-response.md` в конце: при сортировке по имени ответ сразу под запросом, запрос остаётся таким, каким его прислали, а ответ можно дополнять, не трогая запрос.

## Как прислать запрос

1. Файл `ГГГГ-ММ-ДД-ЧЧММССZ-команда-тема-request.md`: дата и время создания запроса в UTC (`date -u +%F-%H%M%SZ`), команда и тема — по-английски, без транслитерации, например `2026-10-29-161220Z-w2c-capabilities-request.md`. Так запросы сортируются по имени в порядке поступления, даже если их несколько за день. В шапке: дата, команда, **коммит контракта**, по которому вы работаете, и `Статус: новый`.
2. Пункты пронумеруйте. Тогда в ответе можно сослаться: «п. 2 — сделано в `abc1234`».

Добавьте строку в таблицу ниже и закоммитьте в `main`.

Запрос может написать и агент, если для задачи нужно изменить API: команда в имени файла — его команда, для самого макета — `mockup`. Контракт и сервер он не меняет: их правит altumur в форке `altumur/consolem` (`CLAUDE.md`, раздел «Контракт API»).

## Ответ

Ответ — файл `ГГГГ-ММ-ДД-ЧЧММССZ-команда-тема-response.md`, с тем же началом, что у запроса, например `2026-10-29-161220Z-w2c-capabilities-response.md`. Начало имени — номер запроса, а не дата файла: ответ, написанный через два дня, всё равно начинается со времени запроса. Настоящая дата ответа (UTC) — в его шапке, «Ответ от ГГГГ-ММ-ДД», и в таблице ниже. В шапке также — ссылка на запрос, разделы — по пунктам запроса, с теми же номерами. По каждому пункту: что решили, в каком коммите сделано и где смотреть (раздел `BACKEND.md`, тест). Когда ответ готов, в шапке запроса и в таблице меняется статус, а в шапке запроса появляется ссылка на ответ.

| Статус | Значит |
|---|---|
| новый | запрос пришёл, ещё не разобран |
| в работе | разобран, делается |
| отвечен | ответ по всем пунктам записан |
| отклонён | не делаем; почему — в ответе |
| заменён | запрос переписан новым файлом (например, под новый контракт); действует новый — ссылка в «Ответ» |
