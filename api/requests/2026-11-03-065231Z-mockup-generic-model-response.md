## Ответы на вопросы раздела 6

### 1. Ложится ли манифест на `UnitKind` без потерь?

**В основном да, но не один к одному, и не по подсистеме.**

**Поле.** Описатель поля — `{type, required, fixed, default, inherit, merge, enum, unique, ref, must_match, schema, bound_to,
credentials, secret_in, schemes}` (`Platform/02-installer/spec/02.1-installer.norms.md:236-252`). У `json` и `int` уже есть
`schema` — это JSON Schema 2020-12 (`:248`, например `VMS/01-cam/cam.subsystem.yaml:248-265`). Её переносим как есть.

Как ложится каждое слово:

| Манифест | `UnitKind` | Замечание |
|---|---|---|
| `type`: string, int, float, bool, list, json, url, blob (`02.1-installer.norms.md:737`) | `type` JSON Schema | `blob` — не значение, а отдельная дверь байтов (`06.1-console.norms.md`, `PUT /<rows>/<id>/<blob_field>`). Нужен `x-ui-widget: file` и отдельная загрузка |
| `required`, `enum`, `default` | так же | `default` бывает шаблоном: `"cam{id}"` (`cam.subsystem.yaml:63`). Его подставляет сервер, форма показывает пустым |
| `fixed` | `x-immutable` | да |
| `inherit`, `merge` | `x-inherit {merge}` | цепь «единица → домен → `inherit`» (`06.7-console.norms.md:319-321`), см. вопрос 2 |
| `unique: true \| canonical` | `x-unique` | `canonical` — сравнение адреса в каноне URL. Судит только сервер |
| **`ref: <sub>/<семья>`** | **`x-ref`** | ссылку на другой объект несёт `ref` (`main`, `camera`: `cam.subsystem.yaml:69`, `:247`), а не `about` |
| `must_match` | только сервер | «у ссылки и цели одно поле совпадает» (`:69`) — ошибкой с указателем |
| `*_secret` | `writeOnly` | ответ маскирует непустой секрет `***` (`06.2-console.norms.md:49`), поэтому `Unit.secrets` собрать можно |
| `bound_to` | **нужно `x-bound-to`** | смена `source` требует вписать пароль заново (`cam.subsystem.yaml:208`, `:729`). Форма должна это знать, иначе потеря |
| `credentials`, `secret_in`, `schemes` | только сервер | правила адреса камеры (`:125-164`), форме они не нужны: отказ с указателем на поле |
| `display.fields`, `options`, `field_help` | `label`, `x-enum-labels`, `description` | да; тексты только русские |
| `display.form` (`title`, `fields`, `note`, `state`, `placement`) | `x-ui-group`, описание группы | да (`cam.subsystem.yaml:723-741`) |
| `display.section`, `unit`, `units`, `units_count` | `label`, `labelPlural` | третья форма, «5 камер» (`:683`), — предлагаем необязательный `labelCount` |

**Что не так в вашем сопоставлении.**
- **`about` — не `x-ref`.** `about: {sub, field}` говорит «строка — о единице другой подсистемы»: права и события идут от неё
  (`VMS/02-rec/rec.subsystem.yaml:63-66`). По смыслу это хозяин, ближе к `parentId`, чем к ссылке. Ссылка — `ref`.
- **`requests.schema` — одна схема на всю подсистему**, с `action` перечислением (`cam.subsystem.yaml:498-519`). Параметры по
  действиям в ней не разделены: `port`, `state`, `pulse_ms` относятся к `output`, `n` — к `preset`. Разложить на `actions[]` можно
  только авторской таблицей: `if/then` по `action` или строки в таблице видов.
- **События — не из манифеста.** `display.kinds` даёт только подписи видов событий (`:757-761`), `events.suppress` — правила
  схлопывания (`:787-`). Какие события поднимает устройство — таблица `cam/devices.events`, своя у каждого устройства (`:278`).
  Каталог событий и действий правил с параметрами — данные `backend`: `VMS/11-backend/data/rule-catalog.json`.
- **`rights.reach` — не `accessLevels`.** Он говорит, что правка поля или действие требуют прав шире единицы: на группу или на
  кластер (`Platform/common/contracts/gate-and-pass.md:397`; `cam.subsystem.yaml:533-537`). Уровни у нас одни на всю систему:
  `view < edit < admin` (`07-console-module.norms.md:105`). Предлагаем `x-rights: {scope: group | cluster}` на свойстве и
  `right: {level, scope}` у действия.
- **Вид ≠ подсистема.** Вот как устроены виды consolem у нас:
  - в `cam/cameras` четыре вида по полю `type` (`cam.subsystem.yaml:234`), плюс потоки — строки с `main`;
  - единицы СКУД и встроенные детекторы — строки таблицы `cam/device_units` (`:320-336`);
  - датчики и реле — `cam/children` с `cam/child_settings` (`:294-316`);
  - канал и хранилище устройства выводятся из `cam/devices` (`mapping.tsv:166`, `:192`);
  - камера целиком — сборка `cam` + `rec` + `det` (`mapping.tsv:44`).

  Какие поля относятся к какому `type`, манифест не говорит: только в заметках формы, например «Только у источника событий (POS)»
  (`cam.subsystem.yaml:737`). Значит, виды и их `if/then` задаёт адаптер, таблицей рядом с `mapping.tsv`.

**Что не выражается и не нужно в `UnitKind`:**
- `placement` — правила контроллера (`:423-484`). Оператор задаёт поля, которые на него влияют (`labels`, `priority`, `live`) — это
  обычные свойства. Где объект в итоге работает и почему — `status`;
- `tokens` (`:589-614`) — механика домена;
- `books` (`:582-586`) — производные данные домена. Книга `licence` уже читается для `/licenses`;
- `metrics` (`:635-678`) — ряды Prometheus;
- `slot`, `lease`, `worker`, `shares`, `door`, `snapshot`, `kept` — устройство процессов.

Всё это не настройка объекта, теряться тут нечему.

### 2. Таблицы, общие настройки домена, задано и наблюдается

**Таблицы — не `shape: document`.** Таблица w2c — набор строк с ключом по шаблону: `"{camera}-{type}-{number:int}"`
(`cam.subsystem.yaml:295`). У каждой строки своя `revision` и свой индекс, `If-Match` на `POST` и `DELETE` строки
(`06.1-console.norms.md:390-422`). `POST` заменяет строку целиком, поэтому `PATCH` адаптер уже сейчас делает слиянием
(`11.4-backend.norms.md:139`). Предлагаем:
- строка таблицы — `Unit` вида `<sub>/<таблица>`;
- родитель — по `rights.unit_of` (`cam.subsystem.yaml:531`: `child_settings`, `device_units` — у `camera`);
- таблицы, которые пишет воркер (`worker.writes`: `devices`, `children`, `found`…, `:34`), — только чтение. По смыслу это скорее
  `status`;
- строки с `delete_after` (`searches`, `found`, `probes`) — данные поиска устройств. Они остаются предметным API.

**Общие настройки домена** — одна подписанная запись на домен `{<sub>: {<имя>: <значение>}}` с ревизией. Пишется
`PUT /domain/shared` с `If-Match` или `base_rev` (`Platform/08-domain/spec/08.9-domain.norms.md:65-99`). **Вот к ней
`shape: document` подходит.** Документ может быть и подсистемным полем, например `licence` (`cam.subsystem.yaml:615-630`).

Наследуемое поле единицы — `x-inherit`. Значение собирается по цепи «единица → домен → `inherit` манифеста», ответ —
`{value, from, inherit, merge?}` (`06.7-console.norms.md:319-321`). Поэтому в `Unit.inherited` поле `from` — не только `uid`, а
`unit | domain | default` (у `domain` — ещё ревизия документа).

**Задано и наблюдается — ложится хорошо.** У строки есть `revision`. Воркер в пульсе отдаёт по единице `phase`, `epoch`,
`observed_revision`, `why` (`Platform/03-worker/spec/03.4-worker.norms.md:42`, `:274`). Контроллер пишет размещение с причиной.
Есть строки состояния `unit.state`, их схема — в манифесте (`06.1-console.norms.md:383-388`, `rec.subsystem.yaml:126-174`).
Отсюда:
- `status.observedVersion` — от `observed_revision`;
- `status.conditions` — от `phase` и `why`;
- `status.observed` — размещение, `serverId`, `unit.state`.

У сборной камеры несколько строк, поэтому `Applied` верно только тогда, когда применились все части. Это условие, а не одно число.

**«Правка, которая идёт не сразу»** (п. 10 запроса `2026-11-01-182545Z`) с `status` решается лучше, чем сейчас. Сейчас мы держим
`PATCH` до 30 с. С `status` можно отвечать сразу, а «ещё не применилось» показывать через `observedVersion` ≠ `version`.
Предлагаем так и сделать на путях ядра.

### 6. Гипотеза на w2c: что лишнее, чего не хватает

- **`Unit`** — да. Наш id уже похож на `uid`: `device:<кластер>/cam/cameras/<id>` (`mapping.tsv:45`).
- **Проекции → профили** — согласны. Оговорка: у нас профиль реализуется сборкой в адаптере по данным `mapping.tsv`. Это и есть
  проекция, только на сервере и для известного вида, а не код плагина.
- **Связи → свойства-ссылки** — согласны, с поправкой: ссылка — `ref`, а `about` — хозяин (вопрос 1).
- **Лишнее для w2c:**
  - `move`: родитель у нас почти всегда неизменен (`main` — `fixed`, `about` у `rec` — `fixed`);
  - `instant`: у нас нет синхронных команд, см. п. 3;
  - `validate` как «что будет»: уникальность, `ref` и `must_match` консоль судит только при записи.
- **Чего не хватает:**
  - `x-bound-to` (секрет сбрасывается сменой поля);
  - `x-rights` (права шире единицы);
  - виды для строк таблиц с хозяином;
  - `from` у наследования: `unit | domain | default`;
  - поля, которые заполняет сервер (`stamp: [by, at]`, `cam.subsystem.yaml:315`, `:519`), — `readOnly`;
  - необязательный `labelCount`.

### 7. Согласны ли с выигрышем и ценой

Частично.
- **Выигрыш для w2c реален,** но он в будущем потоке, а не в нынешнем коде: около 24 из 42 прошлых пунктов не понадобились бы
  (вопрос 4).
- **«Ноль правок» для w2c неверно:** новая подсистема — строка в манифесте `backend` (вопрос 5).
- **Цену для w2c раздел 3 занижает:**
  - контракт, тестовый сервер, тесты и набор в форке делаем мы (`consolem/CLAUDE.md`, «Контракт API»);
  - на стороне курса — переделка нескольких глав V/11 (вопрос 3);
  - сборка камеры не уходит.
- **Баланс:** для расширяемых VMS без ядра нельзя, и для w2c оно тоже окупается, если идти этапами (п. 12).

### 8. CSP консоли w2c и iframe

Факты курса:
- WebUI отдаётся оболочкой `backend` с CSP **ровно** `script-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'self'`
  (`VMS/11-backend/spec/11.1-backend.norms.md:110-115`; `VMS/11-backend/backend.subsystem.yaml:182-184`). Других директив у
  смонтированной оболочки быть не может (`06.5-console.norms.md:77-84`, `:747`);
- сама WebUI — отдельная страница, не в рамке и без `sandbox` (`11.1-backend.norms.md:112-113`).

Что из этого следует:
- `frame-src`, `child-src` и `default-src` в заголовке нет. По стандарту CSP Level 3 при их отсутствии загрузка рамки не
  ограничена. Значит, **iframe с другого источника наша CSP не запрещает** — но и сузить его до источника плагина мы не можем. Это
  вывод из стандарта, браузером мы его не проверяли;
- **страницы плагинов у w2c будут** (ADR-0115): плагин psim — подсистема, его `setup_ui` отдаёт дверь держателя плагина. Это
  **другое происхождение**, не путь WebUI: скрипт плагина не должен ходить в API консоли с кукой смотрящего;
- поэтому `setupUi.url` — абсолютный адрес двери плагина, его даёт бэкенд. Как встраиваем — п. 11 ниже: сначала ссылка во вкладке,
  затем рамка, и тогда CSP оболочки получает `frame-src` только на дверь плагина.

### 9. `revision` как `Unit.version` при слиянии частичной правки

**Да, строгая, без окна гонки — но версия не `revision`, а индекс хранилища.**
- `revision` после удаления и повторного создания может вернуться к прежнему значению. Индекс не повторяется никогда
  (`06.1-console.norms.md:394-395`).
- Бэкенд уже так делает:
  - `If-Match` обязателен (428);
  - версия сборной записи — склейка индексов частей, `c…r…d…h…` (`mapping.tsv:89`);
  - запись — один пакет: записываемые части с `cas` из того же снимка, остальные — стражами. Изменилась любая — 412, не записано
    ничего (`11.4-backend.norms.md:95-104`, `:154-172`);
  - частичную правку строки таблицы адаптер сливает со строкой из снимка и пишет её целиком с `cas` её индекса (`:139`).
- **Предел:** строку, созданную мимо `backend` после снимка, пакет не стережёт. Её покажет следующее чтение как новую `version`
  (`:101`).

## Варианты, которые устроят обе стороны

### П. 8. Подписи с сервера и «сервер отдаёт коды»

Вам нужна подпись незнакомого вида. Нам — чтобы известные слова не начали приходить с сервера разными текстами и чтобы перевод
остался в интерфейсе. Предлагаем:
- описания видов отдают `label: {key, text, lang}`;
- интерфейс сначала ищет `key` в своём словаре (`i18n-en.js` и русская основа) и только без ключа показывает `text`;
- `lang` говорит, на каком языке `text`. У w2c это всегда `ru` (`display` манифеста), а у NGP — язык `Accept-Language`;
- ключ у w2c постоянный, из места в манифесте: `cam.fields.cred_secret`, `cam.options.live.on-demand`. Интерфейс может завести
  перевод для любого ключа, и тогда его слово главнее.

Договорённость в `api/README.md:104` меняется одной фразой: «коды и ключи с сервера; запасной текст — у видов из систем». Всё, что
интерфейс знает, идёт как раньше.

### П. 4. `field` как JSON Pointer

У нас указатель уже норма платформы (`06.1-console.norms.md:357-368`). Модуль консоли ставит ошибку у поля по первому токену
(`07-console-module.norms.md:97-101`). Предлагаем:
- на путях ядра `field` — всегда указатель в теле запроса (`/properties/mode`), без двойной формы. Иначе непонятно, `a/b` — это имя
  или путь;
- на старых путях — имя, как сейчас, пока их не снимут. Клиент различает формы по первому символу `/`;
- `errors[]` необязателен: минимум первое поле, больше — если система может. Наш бэкенд может дать все ошибки проверки по схеме, а
  ошибки консоли — по одной;
- указатель адресует **тело консолем**, а не строку w2c. Перевод `/cred_secret` → `/properties/cred_secret` (или поле профиля)
  делает адаптер.

### П. 12. Порядок перехода

Мы на каждом шаге закрепляем контракт по SHA-256 (`VMS/11-backend/consolem.openapi.json.sha256`) и гоняем ваши тесты API в своём
профиле. Поэтому предлагаем этапы — с одним закреплением на этап, а не на коммит:

| Этап | Что | Почему так |
|---|---|---|
| 0 | договорённости: `field` на путях ядра, `label {key, text, lang}`, смысл `version`, `status`, открытый `TreeNode.kind` и `StreamMessage.kind` | дёшево, нужно всем этапам |
| 1 | ядро только на чтение: `GET /kinds`, `GET /units`, `GET /units/{uid}`, `GET /units/{uid}/schema`; незнакомый вид показывается (сценарий 8) | без риска записи; проверяет перевод манифеста |
| 2 | запись для видов без профиля: `POST`, `PATCH`, `DELETE /units`, действия, шаги `/operations` по `uid`; набор `test.unknown` и строки таблиц w2c | здесь главный выигрыш w2c |
| 3 | профили известных видов: `vms.camera/1`, `vms.archive/1`…; ручные экраны WebUI — на профили; старые пути живы | сборка w2c переводится на профиль, а не переписывается |
| 4 | права и правила: `kindAccess`, события и действия из описаний | у w2c нужен ADR о новой области гранта |
| 5 | снятие старых путей, `DeviceType`, плоского `Device` | только когда бэкенд w2c проходит тесты на этапах 1–4 |

Предлагаем всё это сделать в первой генерации: этапы — не отсрочка, а порядок работ. Кто что делает — как сейчас: контракт и тестовый
сервер в форке — altumur, построитель формы в WebUI — вы, `index.html` — обе стороны.

### П. 11. Страница плагина и CSP

Вам нужно, чтобы автор плагина psim мог дать свой экран. Нам — чтобы WebUI не стала рамкой для страниц под кукой консоли и чтобы
вид настраивался и без страницы. Предлагаем (ADR-0115):
- **общая форма по схеме из `GET /kinds` — всегда.** `UnitKind.setupUi {url, kinds, mode}` — добавка: форма показывает переход на
  страницу плагина, но без неё вид настраивается полностью;
- `url` — абсолютный адрес двери плагина, своё происхождение, не путь WebUI. Параметры — как у psim: `?type=&id=&lang=`;
- **этап 1 — `mode: tab`.** Ссылка «Страница плагина» открывает новую вкладку. Вход — короткий токен страницы в `?t=` первого адреса,
  его даёт бэкенд по праву просмотра вида. Дверь ставит на своём происхождении куки `HttpOnly`, `SameSite=Strict` с путём маршрута
  плагина и перенаправляет на адрес без `t`. CSP `sandbox` на этом этапе не ставим: он дал бы непрозрачное происхождение и сломал
  бы собственные `fetch` страницы psim к своей двери;
- **этап 2 — `mode: iframe`.** Рамка `sandbox="allow-scripts allow-forms"` без `allow-same-origin`. WebUI принимает сообщения только
  от `iframe.contentWindow` и только ваши четыре: `ready`, `height`, `dirty`, `saved`. CSP оболочки получает `frame-src` только на
  дверь плагина;
- права консоли страница не получает ни на одном этапе: пишет она через свой сервер плагина, а WebUI видит итог событием
  `entity.changed` и данным из страницы не доверяет.

### Ещё два предложения от нас

- **Быстрый ответ на медленную правку.** На путях ядра `PATCH` отвечает сразу, а «ещё не применилось» видно в `status`
  (`observedVersion` ≠ `version`, условие `Applied: false` с причиной). Это снимает «держим ответ до 30 с» из п. 10 запроса
  `2026-11-01-182545Z`.
- **Поля по виду устройства.** У нас одна строка `cam/cameras` несёт четыре вида по `type`. Предлагаем разрешить в схеме вида
  `if/then` по полю-дискриминатору — или считать каждый `type` своим видом. Мы выберем второе: так проще мастеру и правам.

## Чего мы не проверили

- рамку этапа 2 в браузере под нашей CSP не проверяли: `frame-src` и `sandbox` — по стандарту, не по опыту;
- появляется ли новая подсистема в консоли без перезапуска (каталог манифестов читается на старте); для ответа это не важно — нужна
  строка в манифесте `backend`;
- раскладку 42 пунктов — только по заголовкам;
- размер `GET /kinds` для w2c не мерили. Оценка: виды `cam`, `rec`, `det`, `auto` и строки таблиц — десятки килобайт;
- что у NGP и psim всё так, как в вашем приложении: это не наша часть, мы не смотрели.
