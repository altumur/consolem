# Запрос от команды w2c: чего не хватает в контракте 0.2.0 плагинам psim

2026-11-05 · контракт 0.2.0, коммит `11f0620` (`api/openapi.json` не менялся до `343678b`) · от команды w2c (бэкенд VMS)

**Статус: новый**

В VMS w2c появляются плагины psim (psim-sdk `c3d9ebb`). Это чужие исполняемые файлы, у каждого свой манифест `plugin.json`. В манифесте описаны:
- виды объектов с параметрами;
- события и команды;
- страница настроек плагина.

Плагин ставят на работающий кластер, консоль при этом не пересобирают. После установки оператор в WebUI видит новые виды. Он создаёт, правит и удаляет объекты, выполняет команды и открывает страницу плагина. Форма строится только по описанию вида: своего экрана под плагин нет.

Большую часть этого 0.2.0 уже даёт. Что именно:
- **описание вида:** `UnitKind` с `origin.plugin`, `setupUi`, `actions`, `events`, `capabilities`;
- **схема полей:** подписи `Text`, `x-ref`, `x-enum-labels`, `writeOnly` и `Unit.secrets`;
- **объекты:** `Unit.status`, `Unit.capabilities`;
- **проверка и правка:** `POST /units/validate`, Merge Patch с `If-Match`;
- **образец:** плагин `security_controller` в `demo.json`.

Мы сверили по пунктам наш прежний запрос, поданный на `a9a96e2` ещё до перехода на 0.2.0. В этом запросе осталось только то, чего в 0.2.0 нет. Прежний запрос вам не отправлялся.

## 1. Страница плагина — адрес на каждое открытие

Сейчас `UnitKind.setupUi.url` обязателен и лежит в описании вида (`openapi.json:16681`). Параметры `?type=&id=&lang=` к нему добавляет клиент (`index.html:3497–3505`). У нас так не выйдет.
- Страница плагина пишет настройки своим сервером плагина. Пускать на неё можно только того, у кого есть право **правки** вида.
- Поэтому адрес у нас одноразовый: сервер выдаёт его на каждое открытие с коротким токеном `?t=`. Получив токен, сервер плагина ставит свою куку и перенаправляет на адрес без `t`.
- Токен живёт минуты, а описание вида кэшируется по `ETag`. Поэтому в `setupUi.url` токен положить нельзя.

Просим:
1. Операцию `POST /units/{uid}/setup-ui` → `200 {url, expiresAt}`. Нет права правки — `403 PERMISSION_DENIED`. У вида нет `setupUi` — `404 NOT_FOUND`.
   - В адресе уже есть всё: токен и параметры psim `type`, `id`, `lang`. Клиент открывает его как есть в новой вкладке и ничего не дописывает.
   - WebUI зовёт операцию при каждом нажатии «Страница плагина».
2. `setupUi.url` сделать необязательным. Есть `url` — постоянный адрес, как сейчас. Нет — адрес даёт `POST /units/{uid}/setup-ui`.
3. Отметку `setupUi` в `Unit.capabilities`, чтобы человек с одним просмотром не видел ссылку, которую сервер отвергнет.
4. Строку в описании `setupUi`: страница — на другом происхождении, куки и токен консоли она не получает, в `/api/*` консоли не ходит.

## 2. Отказ плагина в состоянии объекта

Плагин получает параметры уже после записи. Поэтому `PATCH /units/{uid}` отвечает `200`, а отказ приходит потом. Плагин может быть не запущен, отвергнуть параметры своим текстом, или на сервере может не оказаться пакета плагина. В 0.2.0 для этого есть `status.conditions[]` и `Applied: false`. Но `UnitCondition` (`openapi.json:16833`) — это `{type, status, reason, params, since}`: в нём нет места для текста плагина и нечем подсветить поля.

Просим:
1. Добавить в `UnitCondition` два поля:
   - `message` — текст отказа как есть, на языке плагина. Клиент показывает его без перевода;
   - `fields[]` — JSON Pointer в теле объекта, например `/properties/ip_address`. Форма подсвечивает эти поля.
2. Записать в описании пример: `{type: "Ready", status: "false", reason: "Unfit", message: "…", fields: [...]}`.
3. **Описание наблюдаемого.** Параметры `readonly` плагина пишет сам плагин, у нас они идут в `status.observed`. Это свободный объект без подписей. Форме нужны подписи и типы этих полей. Нам подходит любой из двух вариантов, выберите сами:
   - `UnitKind.statusSchema` — схема `status.observed` с `x-label`;
   - `readOnly`-свойства внутри `schema` с пометкой `x-status: true`, их значения приходят в `status.observed`.

## 3. `x-hidden`

У параметров psim бывает `hidden: true`. Это служебное поле плагина: сервер его хранит, но форма не показывает. Сейчас незнакомое `x-*` клиент пропускает и поле показывает.

Просим добавить в `JsonSchema` ключевое слово `x-hidden: true`. Форма поле не рисует, в `properties` оно приходит, `PATCH` без него поле не меняет.

## 4. Кэш описаний видов

1. **`Vary: Accept-Language`** у `GET /kinds` и `GET /kinds/{kind}`. Подписи (`Text.text`) зависят от языка. Без `Vary` прокси и браузер могут отдать описание на другом языке.
   - Заодно просим поправить описание `Text.lang` («У w2c всегда ru»). У нас, как у NGP, `text` на языке `Accept-Language`, если у плагина есть перевод, иначе английский текст с `lang: en`.
2. **`If-None-Match` и `304` у `getKind`.** У `listKinds` они есть, у `getKind` — только `ETag`.

## 5. Пример вида экземпляра и полей плагина в `demo.json`

Экземпляр плагина у нас — отдельный вид с одним объектом. Его свойства — параметры плагина целиком, например `security_controller`. Создаёт объект установка, удаляет её снятие. Оператор может только смотреть и править. В 0.2.0 для этого уже хватает `UnitKind.capabilities` без `create` и `delete`. Сервер отвечает на `POST` такого вида `422 NOT_SUPPORTED` с `params.capability: create`. Свойство `enabled` — `readOnly`: включает плагин администратор шагом установки.

Просим дополнить плагин `security_controller` в `demo.json`, чтобы WebUI проверил на нём всё, что нужно плагинам:
1. **Вид экземпляра** `security_controller`:
   - `origin.plugin`, `capabilities: []`, один объект;
   - свойство `enabled` с `readOnly: true`;
   - условие `Ready: false` с `message` из п. 2.
2. **У `security_controller/CONTROLLER`** — скрытое поле (`x-hidden`), секрет (`writeOnly`) и наблюдаемое поле (п. 2.3).
3. **У событий `ONLINE` (`info`) и `OFFLINE` (`error`)** — `alarm: false`. Сейчас флага нет, и по умолчанию оба считаются тревогой. У нас тревога — только `alarm` и `critical`.

## 6. Имя вида плагина

В прошлом запросе мы предлагали грамматику имени без `/`. Снимаем: берём вашу форму `<plugin_id>/<тип>`, как `security_controller/CONTROLLER` в `demo.json`. Вид экземпляра — `<plugin_id>`, без `/`.

Просим записать это в описании `UnitKind.kind`:
- имя — непустая строка;
- `/` допустим и в пути кодируется (`%2F`);
- клиент имя не разбирает, плагин узнаёт по `origin.plugin`.
