# Запрос w2c к psim-sdk: доступ плагина psim к объектам и видео

2026-11-20 · w2c · контракт 0.34.0, коммит `c25e3d2`

Кому: владелец контракта

**Статус: в работе**

## Почему запрос здесь

psim-sdk ведёт ваша команда, поэтому запрос к psim-sdk — сюда, тем же путём, что запросы к контракту. Контракт consolem он не
меняет.

Это и ответ на п. 7 запроса [124650Z](2026-11-19-124650Z-owner-setup-ui-step1-request.md) — кто говорит с авторами psim-sdk:
psim-sdk ваш, так что предложение из п. 7 — у вас, от w2c передавать нечего.

## Основание

Плагины psim в w2c переходят в общий урок платформы P/12 «плагины PSIM». Код плагина должен получать доступ к объектам всех
подсистем и к видео только по договору и с проверкой прав. Для этого нужны изменения в psim-sdk.

Урок P/12 принят. До этих изменений часть его этапов закрыта: их проверки дают `not_executed` с причиной. Нормы урока:
P/12.1-R008, P/12.3-R013, R016, R017, P/12.4-R006.

## 1. Видео — только через платформу

1. Вызовы `Platform.OpenVideo(uid, sdp_offer) → {sdp_answer, video_session}` и `Platform.CloseVideo(video_session)`.
2. Видео открывается только через платформу: WHEP по машинному токену держателя доставки. Прямого доступа плагина к потоку нет.

## 2. Полный UID объекта

Полный непрозрачный UID `(origin, kind, localId)` в `Unit` и `ObjectRef`. Так плагин различает объекты разных подсистем.

## 3. Права в `plugin.json`

1. Имя права.
2. Область `view`: `origin`, вид, область единиц.
3. `events` и `commands` — отдельными записями, по операциям подсистемы, которой принадлежит объект.
4. `video` — явный список нативных камер `cam`.
5. Бюджет вызовов: размер и окно. На превышение — `RESOURCE_EXHAUSTED`.

## 4. На будущее: исполнитель страницы плагина

Страницу плагина запускает адаптер в своей изоляции, без канала к процессу плагина и к SDK. Страница пишет только через консоль
платформы, от имени человека. Как и страница в рамке consolem ([120707Z](2026-11-18-120707Z-owner-setup-ui-iframe-request.md),
п. 2), сама она настроек не пишет.
