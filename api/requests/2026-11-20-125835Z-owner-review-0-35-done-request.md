## Что мы сделали

Владелец контракта заказал два ревью: «бэкенд w2c переходит с 0.2.0 на 0.34.0» и «безопасность моста своей страницы». Документы, которые ревью нашло неверными, исправлены без смены смысла (`b090f68`). Решения владельца по остальным находкам вошли в контракт 0.35.0 (`25cbf5b`). Описание — `api/README.md`, разделы «Ломающие изменения в 0.35.0» и «Что добавлено в 0.35.0», и `api/SETUP-UI.md`, раздел «Свой объект (с 0.35.0)».

Вам пишем по двум причинам. Первая: правка задела профиль `vms.camera/1`, а вы его reviewers. Вторая: ломающая часть касается авторов своих страниц подсистем.

## Что проверить

1. **Мост работает только со своим объектом (ломающая правка, `api/SETUP-UI.md`, «Свой объект»).** Свой объект страницы — объект рамки и его потомки по цепочке `parentId`. Бэкенду делать нечего: всё делает consolem, разметка `x-bridge` не изменилась.
   - Команда объекту вне своего (`runUnitAction`, `startDiscovery`, `stopDiscovery`) и команда вида (`runKindAction`) идут только после диалога consolem. Отказ человека — `CANCELLED`.
   - Журнал (`listJournal`, `listJournalFacets`) страница читает только по своему объекту и без аудита. Чужой `deviceId` и `audit` в `category` дают `NOT_SUPPORTED` с полем.
   - `cancelOperation` — только для операций, которые запустила эта рамка.
   - Скрытая страница (другая вкладка карточки, «Все параметры») только читает и получает события. `act`, `draft`, `confirm` и `navigate` получают `BUSY`.

   Своих страниц у w2c пока нет, поэтому сломать нечего. Проверьте, хватит ли этих пределов вашим будущим страницам. Например, нужна ли странице объекта команда родителю без вопроса. Тестовая страница стенда (клавиатура СКУД) ставит на охрану свой контроллер, то есть родителя, и теперь получает вопрос консоли.
2. **Итог круга камер области — профиль `vms.camera/1`.** Новая схема `AreaStateSummary` (`x-layer: vms.camera/1`): `status.observed.stateSummary` у объекта области `{total, offline, silent, at, unread?}`. Раньше поле было только у встроенного сервера, а тест «Домен: status.observed.stateSummary…» требовал его в слое механизма, хотя в контракте поля не было. Теперь тест идёт в слое `profile:vms.camera/1`. Бэкенд без вида камер поле не отдаёт и тест пропускает. Проверьте, что описание полей подходит вашему итогу круга. Особенно `silent` (нет сигнала: связи нет, `fault: drv`) и `unread`.
3. **Устаревшие операции механизма необязательны.** Новый бэкенд может не объявлять `pauseOperation`, `resumeOperation` и пять операций окон обслуживания (устарели в 0.4.0). Паузу `index.html` не зовёт. Окна ассистент читает, только если система их объявила, а иначе кладёт в снимок пустой список (`AssistWorld.maintenanceWindows`). Это ответ на вопрос «делать ли устаревшее» при переходе с 0.2.0.
4. **Правило снятия поля профиля** (`api/profiles/README.md`, «Версии»). Поле, которого нет на особом экране, профиль снимает младшей версией со списком `removed`. Поле, которое экран показывает, снимают только старшей версией. Шага `deprecated` у поля профиля нет. Это заменяет слова пункта 2 в [ответе на вашу позицию по слоям](2026-11-18-114831Z-w2c-contract-layers-response.md) («сначала `deprecated`, потом старшая версия»): там стоит пометка «Уточнено 2026-11-20». mockup в [ответе на 154325Z](2026-11-18-154325Z-owner-profile-files-response.md) пишет: «поле уходит с особого экрана — младшая версия с `removed`». Это то же правило, если сначала consolem убирает поле с экрана, а потом профиль снимает поле. Пока ручные экраны рисуют поле, даже когда сервер его не прислал (правило 2 того же ответа), поле на экране снимают только старшей версией.
5. **Тест механизма строже документа — исправлено (`b090f68`).** Тест «Профили 0.25.0» сверял `version` и `uses` профилей с набором `demo` на любом стенде. Теперь сверка идёт только на встроенном сервере: на вашем стенде `version` необязателен, профили и младшие версии — свои.
6. **Документы для перехода с 0.2.0 (`b090f68`).**
   - `Capabilities.sections` везде описано как обязательное с 0.32.0.
   - Снятое в 0.32.0 больше не названо действующим: README, `BACKEND.md`, `TESTS.md`, описание `UnitBrief.subtype`.
   - 0.23.0 и 0.28.0 названы ломающими.
   - Цель перехода исправлена на нынешнюю версию.
   - В `BACKEND.md` уточнено, у каких профилей есть строки `LAYER`, и добавлен набор `agents` у `/test/reset`.
   - Тестовая страница стенда описана по шагу 2.

   Проверьте, что `api/BACKEND.md` теперь не расходится с тем, что вы делаете.
