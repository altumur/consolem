## 1. Код «нужен супервизор»

**Решение:** добавлен код `SUPERVISOR_REQUIRED`: `403`, `field: /supervisor`. Запасной вариант с `params.reason: required` не нужен, такой ответ замените на новый код.

- Код отдают `createExport`, `checkExport` (в `errors`) и `retryExport`.
- `SUPERVISOR_REJECTED` остался для супервизора, который указан, но не подходит.
- Окно на новый код пишет «Нужно подтверждение супервизора» и открывает поля, даже если `GET /me/export` не сказал о надзоре. Поля остаются открытыми до конца заказа.
- `supervisor` уходит в теле только с логином и паролем вместе. Половина ввода не даёт «пароль неверен».

**Коммиты:** `0fbdd12`, `30c01da`. **Проверка:** тест «Надзор: без supervisor — 403 SUPERVISOR_REQUIRED…», сценарий `ui-export.js`.

## 2. Поля супервизора и `accessSupervision`

**Решение:** признак надзора над выгрузкой один — `ExportGrant.supervisorRequired`.

- Окно показывает поля и шлёт `supervisor` независимо от возможностей.
- Встроенный сервер больше не отвечает `422 NOT_SUPPORTED` на `supervisor`.
- `accessSupervision` отвечает только за правку `Role.supervision`. Описания `ExportCreate.supervisor` и `Feature.accessSupervision` исправлены.

**Коммиты:** `0fbdd12`, `30c01da`. **Проверка:** тот же тест идёт дважды, с `accessSupervision` и без неё; сценарий `ui-export.js` убирает возможность из `CAPS`.

**На что обратить внимание.** `checkExport` отдаёт `SUPERVISOR_REJECTED`, то есть бэкенд проверяет пароль и при проверке заказа. Поэтому окно шлёт проверку по уходу из поля супервизора, а не на каждую паузу в наборе. Кнопка «Экспорт» открывается после ответа этой проверки. Если вы считаете неудачные входы, проверьте, что проверка заказа не запирает учётную запись.

## 3. `PASSWORD_REQUIRED`

**Решение:**

- В контракте записано: система может не отдавать `PASSWORD_REQUIRED` никогда, окно на него не полагается (`ProblemCode`, `createExport`, `ExportCreate.password`, `ExportGrant.passwordRequired`).
- У `403 PERMISSION_DENIED` записана `params.reason: privacy`, `field` — `/cameras/i` или нет. Окно пишет на него текст `ExportGrant.refusal`.
- При `privacyForced: true` и `refusal` окно показывает отказ и не просит пароль, в том числе при повторе.

**Ответ на ваш вопрос об `ExportGrant.devices[]`.** Ваше наблюдение устарело: окно уже читает `devices[]`. Камера без права на вид заказа (`archive: false` для архива, `live: false` для живого кадра) остаётся в заказе с меткой у строки, снимает её человек. Заказ с такой камерой получает отказ сервера у `/cameras/i`. Это записано в описании `ExportGrant.devices`.

**Коммиты:** `0fbdd12`, `30c01da`. **Проверка:** тест «Маска, которую система не делает…», сценарий `ui-export.js`.

## 4. Повтор неудачных частей

**Решение:** в тело `POST /exports/{exportId}/retry-failed` добавлено поле `supervisor` той же схемы, что у `ExportCreate.supervisor`. В операции описаны оба отказа.

- Окно перед повтором читает `GET /me/export` по камерам этого заказа и спрашивает супервизора, если нужен надзор или у прежнего заказа есть `supervisedBy`.
- На отказ с `field: /supervisor` или `/password` окно спрашивает поля снова.

**На что обратить внимание.** `Export.request.supervisor` хранит логин. При повторе его нельзя принять за подтверждение: без `supervisor` в теле повтора ответ — `SUPERVISOR_REQUIRED`.

**Коммиты:** `0fbdd12`, `30c01da`. **Проверка:** тест «Надзор при повторе…», сценарий `ui-export.js`.

## Сверх запроса

- **Сверка ответов** (`api/contract.js`): обязательное `writeOnly`-поле теперь обязательно только в запросе. Иначе `Export.request.supervisor` без пароля не проходил сверку с контрактом. В запросе пароль супервизора обязателен, как раньше. Если ваш стенд сверяет ответы своей проверкой, учтите это.
- **Встроенный сервер проверяет супервизора.** Кто подходит, задаёт стенд: `stand.exportSupervisor {login, password}`, по умолчанию `supervisor` / `supervisor`. Сам автор заказа не подходит. Набор и контракт это не меняет: это только данные стенда.
- **Отказ раньше пароля.** При `refusal` встроенный сервер не добавляет `PASSWORD_REQUIRED` к ошибкам проверки, как у вас.
