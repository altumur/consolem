## Первый черновик (закрыт: ui-draft: checked)

Файл отдельный: `ui-draft-spec.md` и другие заняты прошлыми черновиками (`ui-draft-spec-hranilishcha.md` — соседний открытый черновик).

## Цель

В срезе «Детекторы» администратор работает с детекторами, а не с камерами: при входе сразу видит все детекторы
(что, где, на какой камере, включён ли), может сгруппировать их по виду, найти нужные и сравнить. И может создать
много детекторов сразу на разных камерах прямо из среза, не проваливаясь в каждую камеру: серверные — на любые
камеры, встроенные — на камеры, которые их умеют (одна модель / общий шаблон в `detectorOptions`).

## Проблемы сейчас (index.html, dfd8ad2, 1440×900)

- При входе дерево «папки → камеры»; детекторы за шевронами, сразу не видны. Справа карточка домена, о детекторах ни слова.
- На кнопке среза «Детекторы 0», хотя в наборе их 14: строки кэша без детекторов, считается только раскрытое.
- Виды детекторов не группируются: «все движения» или «все линии» посмотреть нельзя.
- Вверху раздела нет создания детектора: только «+ Детектор» в карточке камеры, вкладка «Детекторы» — по одной камере
  (ещё «Применить к другим…» и «Детекторы» в карточке выборки, но там сначала надо отметить камеры в дереве, и только одной модели).

## Критерии

- Вид: пользователь утверждает экран среза «Детекторы» и путь создания «много детекторов на разных камерах».
- Поведение (проверяется при выходе из черновика):
  - при входе в срез видны детекторы, у каждого читается имя, вид, камера, где работает (на камере / на сервере);
  - кнопка среза показывает настоящее число детекторов;
  - виды детекторов видны в дереве и в быстром фильтре таблицы; отдельной группировки таблицы нет (раунд 3);
  - из шапки среза создаются детекторы сразу на нескольких камерах: серверный — на любые, встроенный — только на те,
    что его умеют; что не подходит, видно до применения с причиной;
  - создание идёт одной групповой операцией `POST /operations` (шаги `create`), частичный отказ показан, «Повторить неудачные» работает;
  - переход детектор → камера и обратно моргает по правилу интерфейса;
  - контракт и сервер не меняются; `python tools/check_ui.py --page <файл>` и `<файл>?selftest` проходят;
  - раунд 2: таблица и камеры в окне создания фильтруются как «Применить к» (чипы по измерениям, счётчик при остальных значениях, второй клик снимает); колонки таблицы сортируются;
  - раунд 2: в дереве под видом сначала камера, имя детектора — только если камера повторяется;
  - раунд 2: окно создания создаёт одно правило на вид (`POST /rules`, «Только журнал» по умолчанию), или добавляет камеры к правилу (`PUT /rules/{id}`), или открывает редактор с готовым событием;
  - раунд 2: после создания идёт очередь зон по детекторам: «Назад», «Пропустить», «Закончить», «Такую же остальным» с подтверждением; зона пишется сразу; очередь запускается и из таблицы;
  - раунд 2: в карточке детектора и камеры есть «Создать правило» и «Добавить камеру к правилу» с «Отменить»;
  - раунд 3: клик по камере в строке таблицы открывает детектор этой строки; срез, раскладка дерева и кнопка «Папки» не меняются;
  - раунд 3: вкладка «Детекторы» камеры — только список; клик открывает карточку детектора, срез не меняется; «назад» возвращает на вкладку камеры; там же «Удалить»;
  - раунд 3: окно создания идёт по шагам; с вкладки камеры шага выбора камер нет;
  - раунд 4: четыре шага; окно 1320×92vh; клик мимо и Escape окно не закрывают, закрывают «Отмена» и крестик;
  - раунд 4: термин «встроенный / серверный детектор», колонка и фильтр «Размещение»;
  - раунд 4: зона в очереди — черновик до «Сохранить и дальше»; «Назад» и «Закончить» с черновиком спрашивают;
  - раунд 6: «Такую же остальным (N)…» открывает окно «План» (камера, детектор, было, станет), «Применить» идёт одной операцией `POST /operations` с «Отменить» в тосте; без детекторов другой формы очередь закрывается, с ними продолжается на них; кнопки нет, когда подходящих детекторов нет.

  - раунд 8: крестик и «Свернуть» оставляют черновик, виден блок внизу справа в любом разделе; перезагрузка не теряет черновик; «Отмена» спрашивает и удаляет; с другой камеры мастер спрашивает, заменить ли черновик.

## Что есть в API (проверено)

- `POST /operations`, шаг `create` — создать дочернее устройство (детектор), частичный успех, повтор неудачных.
- `Device.detectorOptions` — что умеет камера (шаблон, вид, чувствительность, конфликты), `DeviceCreate.template`/`builtin`.
- `GET /devices?type=det` — строки детекторов; `noDetector=<вид>` — камеры без детектора этого вида.
- В наборе `demo.json` `detectorOptions` есть у 6 камер двух с лишним моделей, детекторов 14 (12 — на «Главном входе»):
  список будет короткий, но набор общий, менять только запросом.

- Правило: несколько событий значат «все за окно» (`rule.noWindow` при `windowSec: 0`, `api/rule-engine.js:453`), поэтому одно правило на вид. Событие детектора стоит на камере, `RuleTarget.fromEvent` — камера из события.
- Зона — в долях кадра (`DetectorZone`), поэтому копия ложится на любой кадр, но сцена там другая.
- Пункт 8 правок пользователя в сообщении раунда 2 пуст: уточнить.

## Решения пользователя

- Раунд 2: правило при массовом создании — вариант A (новое правило в окне, одно на вид). Правила на каждую камеру и шаблона с экземплярами нет.
- Раунд 9: выбор «Записывать / Тревога / Настрою сам» убран: форма правила одна, по умолчанию «То» — запись с камеры события на 10 минут. Отменяется легко, если выбор нужен.
- Раунд 8: всё, что шло после мастера (очередь зон, редактор правила), теперь шаги мастера. Очередь зон осталась только для существующих детекторов («Нарисовать зоны» в таблице). Черновик живёт в `localStorage` этого браузера (`cfg.detCreate`), на сервер не уходит. Крестик не удаляет черновик: удаляет только «Отмена» с подтверждением. Заменяет первую часть решения раунда 7.
- Раунд 7: событие: свой вид из `reference.ruleTriggers`, иначе `det/other` с `match.template` (встроенный) или `match.detectorKind` (серверный). Поле `match.detectorKind` ждёт подтверждения: запрос mockup.
- Раунд 6: «Такую же остальным» — действие, а не переключатель: применяет зону через план и завершает очередь.
- Раунд 5: флажок «Сначала «Только журнал»» выключен по умолчанию.
- Раунд 5: виды детекторов — с сервера: серверные из `GET /reference` → `detectorKinds` (без `other`), встроенные из `Device.detectorOptions`. Подписи кодов — в интерфейсе (`api/README.md`, «Тексты»). Чувствительность серверного детектора при создании не задаём: диапазона в контракте нет.
- Раунд 4: окно создания — 4 шага (Что создать, На каких камерах, Правило, Зона и проверка). Окно больше, а не правая часть экрана: правая часть 892×844 при 1440×900, окно 1320×828.
- Раунд 4: термин — «встроенный детектор» (Embedded в документации Axxon One), а не Edge: edge бывает и сервером рядом с камерой. Пользователь подтвердил. Имена шаблонов «Движение на камере» приходят из набора, менять только запросом.
